# 故障排查

wt-go 将已知失败编为 `E1xx`（启动前）、`E2xx`（设置与桌面操作）与 `E3xx`（运行期）。排查顺序：**先跑 `wt-go diag`，再看 `wt-go.log`，最后看源码**。

## 1. 获取现场与 `wt-go diag`

```pwsh
.\build\windows-amd64\wt-go.exe diag           # 完整状态检查
.\build\windows-amd64\wt-go.exe diag --json    # JSON 输出
.\build\windows-amd64\wt-go.exe diag --redact  # 个人路径脱敏（可贴进 issue）
Get-Content "$env:LOCALAPPDATA\wt-go\wt-go.log" -Tail 50   # 便携版为 data\logs\wt-go.log
```

输出字段说明：`portable:` 仅便携版打印；`conpty:` 说明 Windows 控制台是随包 ConPTY、`$MYGO_CONPTY` 还是系统 conhost；`checks:` 全部通过打印一行，失败逐条输出 `FAILED <编号> <细节>`。退出码：`0` 正常完成检查（即使设备检查失败），`1` JSON 序列化出错，`2` CLI 参数错误。`--redact` 在 Windows/macOS 下大小写不敏感匹配个人目录，Linux 精确匹配。

**文件位置速查**（安装版平铺于 `%LOCALAPPDATA%\wt-go\` 或 `~/.config/wt-go/`；便携版位于 exe 旁 `data\`）：

| 文件 | 安装版 | 便携版 |
| --- | --- | --- |
| 配置 / 窗口几何 | `settings.json`、`window-state.json` | `data\config\settings.json`、`window-state.json` |
| 运行日志 | `wt-go.log`（>1 MiB 下次启动轮转为 `.1`） | `data\logs\wt-go.log` |
| 崩溃日志 | `crash-<yyyyMMdd-hhmmss>.log` | `data\crashes\crash-<yyyyMMdd-hhmmss>.log` |
| 坏配置归档 | `settings.json.bad-<yyyyMMdd-hhmmss>` | `data\config\settings.json.bad-<...>` |

Linux 反馈环境信息可附：`uname -a`、`$XDG_SESSION_TYPE $XDG_CURRENT_DESKTOP $WAYLAND_DISPLAY`、`ldd --version | head -1`、`fc-list :lang=zh | head -3` 与前台运行 `./wt-go` 的输出。

## 2. `wt-go mcp` 诊断服务

`wt-go mcp` 提供只读 MCP 服务器（JSON-RPC 2.0 over stdio，协议版本 `2025-06-18`，一行一个 JSON 对象，不依赖网络或窗口运行）：

```json
{
  "mcpServers": {
    "wt-go": {
      "command": "D:\\path\\to\\wt-go.exe",
      "args": ["mcp"]
    }
  }
}
```

- **工具（5 个）**：`wtgo_diag`（建议首选，同 `wt-go diag` 文本）、`wtgo_status`（完整报告 JSON）、`wtgo_settings`（设置路径、解析状态与核心字段）、`wtgo_profiles`（本机 shell 与合并后 profile）、`wtgo_log`（参数 `lines` 1–2000 默认 120，`path` 留空取最新崩溃日志，单文件 >1 MiB 仅读尾部）。
- **资源（2 个）**：`wtgo://diag`（`text/plain`）、`wtgo://status`（`application/json`），不支持订阅或变更通知。
- **隐私提示**：`wt-go mcp` 输出真实本机路径（不走 `--redact`），接入远端 agent 前请留意路径信息。

## 3. 故障码

### 启动前（E1xx）

- **E101 一个 profile 都起不来**：合并后所有 profile 指向的程序均不可执行（`diag` 的 `profile:` 全 `missing` 或 `0 profiles`）。检查系统 `PATH` 与 `System32`，或在 `profiles[].command` 中填写绝对路径。
- **E102 找不到 libghostty-vt**：`diag` 的 `native:` 为 `not found`。插件按 `$MYGO_GHOSTTY_VT` → 打包资源 → exe 同目录 → `%LOCALAPPDATA%\mygo\natives\<sha256>\`（Linux `~/.cache/mygo/...`）依次查找，都没有才联网下载。裸 `go build`/`go run` 无法下载时请配置 `HTTPS_PROXY` 或手动将库放到 exe 旁。
- **E103 设置目录不可用**：安装版 `%LOCALAPPDATA%` 不可写或未设置，或便携版 exe 所在目录只读。检查目录权限，或将便携文件夹移到可写目录 / 删除 `data` 目录回退安装版。

### 设置与桌面操作（E2xx）

- **E201 settings.json 不是合法的设置**：JSON 语法或结构错误（窗口已回退默认值，原文件已备份为 `settings.json.bad-<时间>`）。看 `diag` 的 `settings:` 或设置页顶部 `E201:` 提示修正，或删掉文件重建。
- **E202 某个字段超出范围**：数值越界（如字号、透明度）。按 `diag` 或设置页红色横幅点名字段对照 [配置参考.md](配置参考.md) 第 4 节修正。
- **E203 某个键位读不出来**：`keybindings` 中某条 `key` 非法，**仅丢弃该条**（不回退默认键）。按 `last fault:` 原文对照 [配置参考.md](配置参考.md) 第 6 节键名表修正。
- **E204 字体族不是等宽字体**：`font.family` 首个可用族非等宽（或整列都无法画格子），终端已跳过它、改用列表中下一个等宽的族，整列都不行才回落到 `monospace`（避免比例字体撑宽字距）。在设置页字体栏 `＋` 菜单选等宽族，或写 `"<族名>,monospace"`（Linux 可用 `fc-list :spacing=mono family | sort -u` 查看）。
- **E205 settings.json 写不进去**：首次探测写入 `settings.json` 失败（权限或被锁）。本次会话内存可用，但文件内无探测条目；修复权限后可在设置页「高级」点「重新探测」。
- **E206 删不掉 settings.json**：「重置」时文件被编辑器/杀软占用或目录只读。关闭占用进程重试或手动删除后重启。
- **E207 重启失败**：「重置」已删掉配置，但拉起新进程失败（exe 被占用或无权限）。手动重新启动即可。
- **E208 打不开目录**：调用 `explorer.exe` / `xdg-open` / `open` 失败。安装 `xdg-utils` 或按 `diag` 路径手动打开。
- **E209 打不开链接**：打开网址（Windows 走 `ShellExecuteW`）或终端输出路径失败；「关于」弹窗打开项目主页走同一条路径，失败时在弹窗内显示该提示。Windows 常见原因为 `error 31`（无默认关联程序或 Scoop 升级后浏览器路径变更导致 `UserChoice` 失效，在「系统默认应用」重设即可）；Linux/macOS 检查浏览器与 `xdg-utils`。注意：点击终端内不存在的文件路径属于无操作，不会记 `E209`。
- **E210 打不开设置文件**：底栏「打开设置文件」调用桌面编辑器失败（Linux 常见于未关联 `.json`）。安装编辑器关联或改用「高级 → 设置目录」手动打开。
- **E211 某个 profile 没出现**：`profiles[]` 存在空 `id` 或重复 `id`（已跳过该条，其余照常）。查看 `wt-go.log` 中下标（如 `profiles[3].id`）并改为唯一非空 `id`。

### 运行期（E3xx）

- **E301 某个 shell 起不来**：profile 指向的可执行文件不存在或无执行权限（得到空标签）。对照 `diag` 的 `profile:` 与 `wt-go.log` 中的原话修正 `profiles[].command` 或删除该条目。
- **E302 窗口因为 panic 停掉**：程序异常崩溃，堆栈写入 `crash-*.log`。请将 `diag`、日志末尾与崩溃日志前 40 行提交 issue。
- **E303 读不到进程列表**：读取系统进程表失败（权限/沙箱/容器未挂 `/proc`），关闭标签时无法判断是否有程序在跑并保守弹窗询问。恢复权限或设 `confirmClose: "never"`。
- **E304 没认出标签的 shell**：启动 3 秒内未等到子进程、终端提前退出或关闭时仍无关联 shell PID。若日志为 `the terminal ended ...` 多为命令行写错或 shell 秒退；否则多为首启较慢，重开标签即可或设 `confirmClose: "never"`。
- **E305 找不到 fontconfig**：Linux 下未加载 `FcConfigGetCurrent` / `FcConfigParseAndLoadFromMemory`，无法注入 `rgba=none` 保护，可能导致文字发白发绿。安装 `fontconfig` 后重启即可。
