# 使用说明

wt-go 是一个 Windows Terminal 风格的终端：标签、分栏、profile、配色方案、可配置快捷键，
配置文件是一份手写友好的 `settings.json`。这份文档讲怎么用；字段逐个说在
[配置参考.md](配置参考.md)，默认键位与键位写法在 [键位.md](键位.md)，
Linux 的依赖与限制在 [Linux.md](Linux.md)；代码地图见 [代码导读.md](代码导读.md)，
取舍理由见 [decisions.md](decisions.md)，阶段状态见 [plan.md](plan.md)。

## 1. 运行环境

- **Windows 10 1809+ / Windows 11**：主要支持与验证目标，用 ConPTY 起 shell。
- **Linux / macOS**：有 pty 与平台路径实现，可交叉编译，属实验性，见 [Linux.md](Linux.md)。
- **Go 1.27+**（`go.mod` 写 `go 1.27.3`）。
- **mygo v0.8.3+**：终端内核来自它的 `plugins/terminal`（libghostty-vt）。
- 发布产物是便携包：`wt-go.exe` 与同目录的 `ghostty-vt.dll`，解压到任意位置双击即用，
  无 Electron、无 webview、不写注册表。

## 2. 构建与运行

```pwsh
pwsh .\Scripts\build.ps1                  # 产物固定为 build\windows-amd64\wt-go.exe
.\build\windows-amd64\wt-go.exe
```

产物固定在 `build\windows-amd64\wt-go.exe`，方便反复真机测试（`build\` 已在 `.gitignore` 里）。
脚本还有三个开关：

| 参数 | 作用 |
| --- | --- |
| `-Test` | 编译前先跑 `go vet ./...` 与 `go test ./...`（和 CI 一样全跑，不只 `./internal/...`） |
| `-Clean` | 先删掉 `build\` 再编译 |
| `-Package` | 换成 mygo 打包，产物在 `dist\`（不造安装器） |

正在运行的那个 exe 占着输出文件时 Windows 会拒绝覆盖，脚本会报出 PID 并停下，关掉窗口再编译即可。
开发时也可以直接用 `go run .`。

窗口的新标签默认开在哪由 profile 的 `dir` 与 `startDirectory` 决定（见第 3 节）；命令行上的
`-d <目录>` 为这一次运行盖上书签，优先级高于 `startDirectory`，profile 自己写死的 `dir` 仍然更具体：

```pwsh
.\build\windows-amd64\wt-go.exe -d D:\work      # 新标签开在 D:\work
.\build\windows-amd64\wt-go.exe -d home         # 家目录；current 是启动时的目录
```

发布包用 mygo 自己的构建命令，
它把原生库、`.deb`、`.tar.gz`（含 `install.sh`）与 `PKGBUILD` 一起产出：

```pwsh
go tool mygo build -platform windows/amd64 -o dist
```

版本号与包名写在 [mygo.json](../mygo.json)；Linux 的运行库依赖见 [Linux.md](Linux.md)
（`mygo.json` 的 `linux.depends` 是空的，安装器不替你装 GTK）。版本号只有这一处：
`mygo build` 把它写进 exe 的版本信息，`Scripts/build.ps1` 打完还会从 exe 属性里读回来对账，
对不上就报错。它是语义化的三段 `主.次.修订`（如 `0.3.0`）：`0.x` 期间还不承诺兼容，不兼容的改动
升次版本号（`0.3.0` → `0.4.0`），新功能与修 bug 只升修订号。改版本不发版：

```pwsh
pwsh .\Scripts\build.ps1 -Version 0.3.0   # mygo.json 里不是这一串就直接失败
```

发布用标签触发（标签与 `mygo.json` 的 version 必须一致，CI 会拦）。三步：改 `mygo.json`
的 `version` → 提交推到 `main` → 打带注释的标签推上去：

```pwsh
git tag -a v0.3.0 -m "wt-go 0.3.0"
git push origin v0.3.0
```

标签只接受三段纯数字：`v1.0.0-rc.1` 这类预发布标签与 build metadata 现在会被 CI 拦下
（CI 与两个构建脚本各有一份认版本号的正则，要发就先一起改）。

`wt-go version` 一行里有两个版本，各说各的：`wt-go v0.3.1-dev (packaged 0.3.0) 096a3a34d115` ——
`(packaged …)` 是 `mygo.json` 宣布的发布版本（脚本与 CI 构建时才有，裸 `go build` 没有），
前者是 Go 的 build info：本地仓库里能算出下一个版本，浅克隆的 CI 里只会写 `v0.0.0-dev`；
提交哈希后的 `+dirty` 说明工作区没提交。

标签触发一次发布，产出 Windows 与 Linux 两个便携 zip（`wt-go.exe` + `ghostty-vt.dll`、
`wt-go` + `libghostty-vt.so` + `wt-go.desktop`，各自带 `LICENSE`），没有安装器、也没有 `.deb`；
清单见 [README](../README.md) 的「快速开始」。解压后直接运行，设置与配色方案仍在用户配置目录
（Windows `%LOCALAPPDATA%\wt-go\`，Linux `~/.config/wt-go/`），换一个解压位置不会丢配置。

exe 的图标、「属性 → 详细信息」与 manifest（高 DPI、控件外观）都由 `go tool mygo build`
在打包时注入，`Scripts/build.ps1`（Windows）与 `Scripts/build.sh`（Linux/macOS）走的也是这条路，所以本地构建的 `wt-go.exe` 与发布版一致
（版本号取自 `mygo.json`）；`go build` 直接出的裸 exe 没有这些资源。改了
`resources\icon.png` 的图案后重画一次：

```pwsh
go run ./tools/genicon           # 重画 resources\icon.png
```

原生库 `libghostty-vt` 的查找顺序是 `$MYGO_GHOSTTY_VT` → 打包资源 → 可执行文件同目录 →
`~/.cache/mygo/natives/<sha256>/`，都没有才联网下载（2 分钟超时、SHA-256 校验）。
断网环境下把它放到 `wt-go.exe` 旁边即可。

## 3. 窗口与标签

标签栏就是窗口标题栏：空白处可拖动窗口，双击切换最大化。三个平台都一样，标题栏的配色与终端一致，
不受桌面主题影响；活动标签就是终端的底色，与下面窗格连成一片，所以它比标签栏矮一点、四角是圆的、
与窗口左边留一道缝，顶边还有一道 2 DIP 的强调色细线（主题的强调色，一般就是方案调色板里的蓝）
——标签与窗格同色时靠它一眼分辨。标题栏高 40 DIP，与 Windows Terminal 的一样高。
Linux 上窗口按钮的**位置与顺序跟随桌面**（`gtk-decoration-layout`，GNOME 默认在右侧、
Ubuntu 在左侧），Wayland 下由合成器画标题栏的桌面（KWin、Hyprland、Sway）则不画，交给合成器。

每个标签名字前面有一块 16 DIP 的方块：底色是该标签运行的 profile 的颜色（内置 shell 的颜色列在
`internal/profile/profile.go` 的表里，`wsl:` 的发行版是 Ubuntu 的橙），中间是终端记号；设置页那个
标签是强调色的方块配一个齿轮。颜色浅的（Command Prompt 的浅灰、Zsh 的暗金）自动换深色记号，
不会白字糊在浅底上。没配颜色的 profile 用一块安静的灰方块，但记号仍是亮的，不会变成一团灰。
不在前面的标签只把方块淡一档，记号不变暗——名字已经说了哪个在前。

`+`、`▾`、滚动用的 `❮`/`❯`、标签上的 `×` 在指针移上去时浮出一层更亮的底色、图标变亮，
与窗口右上角的三个按钮一致；其中关闭按钮悬停时底色变红（Windows 的做法）。

| 操作 | 方式 |
| --- | --- |
| 新建标签 | `Ctrl+Shift+T`（或 `Ctrl+T`）、条带上的 `+`、右键菜单 |
| 切换标签 | `Ctrl+Tab` / `Ctrl+Shift+Tab`、`Ctrl+1`…`Ctrl+9`、点击、`Ctrl+滚轮` |
| 关闭标签 | 标签上的 `×`、中键点击、右键菜单（`confirmClose` 为 `running` 时，标签里还有程序在跑就先问一句） |
| 重命名 / 置色 | 右键菜单；颜色默认随 profile。设置标签页不是终端，右键菜单只有关闭项（没有重命名、复制） |
| 拖拽排序 | 按住标签左右拖（按名字或空白处都行） |
| 标签放不下时 | 标签条自己横向滚动：两端出现 `❮`/`❯`（`❯` 在 `+` 左边），一次一个标签；滚轮直接拨；到头的那个按钮变淡 |
| 用某个 profile 新建 | 标题栏的 `▾` 下拉菜单，或 `Ctrl+Shift+1`…`Ctrl+Shift+9` |
| 新标签的位置 | `newTabPosition`：`last`（默认）或 `first` |
| 标签宽度 | `tabWidth`：`compact`（默认，随名字，但不超过分给它的那一格）或 `equal`（所有标签一样宽，平分标签条） |

新标签开在哪个目录：先看 profile 的 `dir`，再看 `startDirectory`；两者都空时开在**主目录**。
想跟随启动 wt-go 时所在的目录就写 `current`，想固定家目录就写 `home`，不必再写平台各异的
`%USERPROFILE%`、`~`。文件管理器的「在此打开终端」只会把目录交给进程的 cwd，与图标启动分不开，
所以要落在那个目录得用 `-d "$PWD"` 那样的参数（或在设置里写 `current`）。
命令行上的 `-d <目录>` 为这一次运行顶替 `startDirectory`（profile 的 `dir` 仍更具体）。复制标签是例外：
`Ctrl+Shift+D` 直接用当前窗格所在的目录。写法与展开规则见 [配置参考.md](配置参考.md) 第 5 节。

标签名跟随 shell 报告的标题；`titleFromActiveTerminal` 为真时也随有焦点的窗格变化。
「关闭窗口前确认」（`confirmCloseWindow`，默认开）管的是**窗口带着的标签**：窗口里开着两个及以上标签时，
标题栏的 `×` 与 `Alt+F4` 都会先问一句「关闭窗口？」，并告诉你一共有几个标签会跟着走；答「取消」窗口留着、
什么都没动。只开着一个标签时不问——那时关窗口就是关那个标签，没什么可选的；一个个关到最后一个标签也不问，
每次关闭都是自己点的。未保存的设置改动仍由关设置标签那一问把守（见下）。

所有弹菜单（标签右键、`▾`、终端右键、编辑菜单）都**画在窗口里**，用窗口自己的主题色，不是桌面的原生菜单：
原生菜单在深色窗口旁边像另一个程序的。键盘照样能用：上下键、回车、`Esc`、首字母、子菜单的左右键。
`▾` 菜单最下面是「设置」与「关于」；「关于」也可以从命令面板打开，它写着版本（带打包时的版本号）、提交、
mygo 与 Go 运行时、窗口的 `settings.json` 与 `wt-go.log` 路径、许可与项目主页，最后一个可以在浏览器里
打开（打不开时对话框里会说一句）。

标签再多也不会把名字和 `×` 挤没：每个标签有最小宽度，放不下时是标签条滚动，不是标签压缩。
标签跟着窗口变宽：标签少时每个标签最多 240 DIP（`compact` 里名字短的还更窄），标签多了各自变窄，
窄到「色块 + 名字 + `×`」放不下就不再窄，再多就滚动。
相邻两个标签之间有一条 1 DIP 宽的竖线；在前的那个是深色圆角、名字加粗，它两侧不画线。不在前面的标签
名字也是正文色，不压暗，只有名字前的色块淡一点。活动标签顶上没有额外的强调线，靠那层深色加圆角分辨。
`+` 两侧各一条竖分隔线、然后是 `▾`（`+` 紧贴着在前的标签时左侧那条不画，与那两种标签间一样）：
这一组跟在最后一个标签后面，但**不在滚动的标签里**——标签放得下时它们
紧贴最后一个标签，放不下时它们贴到 `❯` 右边固定住，所以再多标签也是一个标签的距离就能新建，不用滚到最后；
右边仍留一段固定的空白专门用来拖窗口，所以标签排满时窗口照样能拖。

## 4. 分栏

一个标签是一棵窗格树，最多 `maxPanes` 个窗格（默认 4，`0` 为不限）。

| 操作 | 方式 |
| --- | --- |
| 自动切分（先竖后横） | `Alt+Shift+D` |
| 纵向切分（左右） | `Alt+Shift+Right` |
| 横向切分（上下） | `Alt+Shift+Down` |
| 焦点移到相邻窗格 | `Alt+左/右/上/下`，或点击 |
| 关闭窗格 | `Ctrl+Shift+W`（最后一个窗格时关标签） |
| 关闭标签内其它窗格 | `Alt+Shift+W` |
| 调整比例 | 拖动窗格之间的分割线（每格至少 40dp） |

焦点移动按几何判定：同方向、跨度重叠最多者优先，其次最近 —— 树序不等于视觉相邻，
所以 `Alt+Left` 一定去左边那个，而不是"树上的上一个"。

## 5. 快捷键

默认值与 Windows Terminal 对齐，全部可在 `settings.json` 覆盖，或在设置页「操作」分组里录制。
最常用的几条：`Ctrl+Shift+T` 新建标签、`Ctrl+Tab` 切换标签、`Alt+Shift+D` 切分窗格、
`Alt+方向键` 移焦点、`Ctrl+,` 打开设置、`Ctrl+Shift+F` 查找、`Ctrl+Shift+P` 命令面板。

按住不放时只有翻标签、移焦点的动作会连发，其余一概按一次执行一次：`Ctrl+T` 按住不会连开标签
（ADR-74）。

完整的默认键位表、动作名与键位字符串的写法在 [键位.md](键位.md)。

## 6. 设置文件

配置是一份 `settings.json`（Windows `%LOCALAPPDATA%\wt-go\settings.json`，
Linux `~/.config/wt-go/settings.json`），首次启动写入默认值，之后热监视并热重载，约一秒内生效。
写盘走临时文件加原子替换；解析失败或数值越界时继续用当前可运行的值，并把坏内容归档成
`settings.json.bad-<yyyyMMdd-hhmmss>`，原因显示在设置页底部。

同一个目录里还有一份 `window-state.json`：窗口的位置、大小与是否最大化。关窗或退出时写入，
下次启动就开在那儿（记下的位置已经不在任何连着的屏幕上时按记下的尺寸居中）；没这份文件时
按 960×600 居中。它不在设置页里，也没有对应的字段——想固定一个大小就在界面上调好再关窗。

全字段、完整示例、数值范围与路径写法见 [配置参考.md](配置参考.md)。

## 7. profile

### 7.1 从哪来

窗口只在**写第一份 `settings.json`** 的时候扫描一次这台机器上能跑的 shell，把它们作为 profile
写进 `profiles`，设置页里带「内置」小标签。之后 `settings.json` 就是唯一来源：改它、删它、加自己的条目
都算数，启动时不会再探测一遍，你改过的命令行也不会被盖掉。想按现在装的东西重来一次，用
设置页「高级」里的**重新探测**（见第 9 节「高级」页）。

Windows 上按 PATH 找程序：`pwsh.exe`（PowerShell 7）、`powershell.exe`、`bash.exe`、`cmd.exe`、`nu.exe`；
再是注册表里 `wsl` 的每个发行版（`wsl.exe -d <发行版名>`）。**只看 PATH，不去猜安装位置**：
装在 PATH 之外的 shell 不会自动出现，需要自己在设置页加一个 profile。
`C:\Windows\System32\bash.exe` 是 Windows 留给 WSL 的转发壳（跑的就是默认发行版），不算单独的 Bash。
注册表里由别的程序给自己登记的发行版不列：Docker Desktop 运行时会写入 `docker-desktop` 与
`docker-desktop-data`，在里面开标签没有任何可交互的东西（名字不分大小写）。

POSIX 上用 `$SHELL`、`/etc/shells` 里认识的 shell（bash、zsh、fish、sh、dash、ksh、tcsh、nu、pwsh；
跳过 `git-shell`、`rbash` 一类），最后 `/bin/sh` 兜底。

程序不在了（卸载了、挪了位置），那个 profile 在你点「重新探测」时被**隐藏**而不是删掉：
重新装回来再探测一次，它还在文件里，点「显示」就回来了。

### 7.2 改、删、隐藏

- 带「内置」的条目可以改名、改颜色、改命令行，改完点保存即可；重新探测会把这些命令行换成现在装的那份，
  名字、颜色、目录保留。
- 带「内置」的条目卡片底部还有一个**重置为内置**：它只问这台机器现在怎么样（只探这一次，不动别的条目），
  把程序与参数换成探测到的、名字与颜色换回内置表说的、隐藏的重新显示，**目录保留**（那是你选的，机器不知道）。
  想一次把全部内置条目换掉用第 9 节「高级」页的「重新探测」。
- 「删除」对这些条目是隐藏：探测时还能找到它，删不掉，所以页面给它们的按钮叫「隐藏」。
- 自己加的条目（不带「内置」）同时有「隐藏」与「删除」：删掉就从文件里没了，隐藏则留着条目随时能找回来。
- 隐藏的条目**仍在左栏的列表里**，名字变灰、行尾带一个「已隐藏」徽标；点开它，右侧的「隐藏」开关
  关掉、保存就回来了。隐藏的条目不出现在新标签菜单与「默认配置文件」的选项里。徽标（「内置」「已隐藏」）
  一律靠右排，所以一列名字下面是一列对得齐的小标签。
- 「图标」是标签前那块方块里的标记，三种选法：**跟命令走**（按程序名认：`pwsh` 认作 PowerShell 7、
  `powershell` 认作 Windows PowerShell、`cmd` 认作 Command Prompt、`bash` 认作 bash，认不出来画普通
  终端图标）；**12 套内置图形**（四种形状各三套配色；图形自带颜色，所以这时「图标颜色」不生效）；
  或者**你自己写的一个字符**（emoji 也行，画在「图标颜色」的方块上）。标记、颜色与名字改完保存后，
  **已经开着的标签也跟着换**，不用重开；标记只属于标签，改它不会重启终端里跑着的程序。

设置页的「配置文件」页编辑的是**副本**，点保存才写回，所以只是看一眼不会把结果写进文件。
字段：`id`、`name`、`command`、`args`、`dir`、`color`、`icon`、`hidden`、`discovered`。重置与「隐藏」一样直接写进这份副本
（于是页面立刻标出「未保存」，点保存才落到文件），点「放弃」就全部退回文件里的样子。

「命令行」留空时，字段下方会用内联提示说明这条 profile 将运行系统的默认 shell，并给出填自己程序时的
一个例子（Windows 上是 `pwsh.exe`，其它系统上是 `bash`）；填了路径，提示随之消失。带「内置」的条目
由窗口探测得来，命令行是探测到的路径、在页面上只读，并注明「这里不改它的路径」。

### 7.3 默认配置文件：跟随设备

设置页「常规与启动」页的「默认配置文件」是「跟随设备（`PowerShell 7`）」加每个 profile，括号里是这台机器
上要跑的那个 shell 在名单里的名字（探测到 `cmd` 就写「Command Prompt」）。选它时 wt-go
**自己解析这个设备**：拿启动时探测到的第一个 shell，用它的程序与参数开标签，名字与颜色取内置表
（`pwsh7` 就叫 `PowerShell 7`，`cmd` 就叫 `Command Prompt`），
标签因此有 profile 名、有颜色，`settings.json` 里不写 `defaultProfile`。`▾` 菜单里那一项也只列
「跟随设备（`PowerShell 7`）」，与设置页写同一个名字。

探测顺序就是内置表的顺序：`pwsh7` → `powershell` → `bash` → `cmd` → `nu` → `wsl:*`
（`wsl:*` 按发行版的先后）。它和终端自己的兜底顺序（Windows 上 `pwsh.exe` →
`powershell.exe` → `%COMSPEC%` → `cmd.exe`；POSIX 用 `$SHELL`，macOS `/bin/zsh`，以登录 shell 起）
只在「机器上有 Git Bash、却没有 pwsh 和 powershell」这类情形下不一样：那时 wt-go 按
`bash` 起，终端自己会去用 `cmd`。按设备的说法跟 Windows Terminal 一样，但它宁可说出要跑什么，
也不把这件事交给终端。

设备是每次启动重新探的：这台机器上新装了个 shell，重开窗口下拉就跟着变，不用去「高级」页点探测。
设置里改过的命令行不受影响（那是 `profiles` 的事，不是设备的事）。

**设备不看设置里的 profile**：哪怕 `pwsh7` 那条被你隐藏了、或者改成别的命令行，跟随设备仍然
用探测到的 `pwsh` 与内置表的名字。隐藏的含义是「别在菜单里提供它」，不是「这台机器没有它」；
把隐藏条目的名字、颜色、参数借给设备，会让「跟随设备」变成「跟随某一条设置」。

选中的 profile 后来被隐藏或删掉了，就回到跟随设备，而不是悄悄换成列表里的另一个。
隐藏的 profile 既不在这个下拉里，也不在 `▾` 菜单里：它运行时会回到设备 shell，列出来就是
一个不成立的选项。所以每个 profile 都被删掉或隐藏起来时，`▾` 菜单只剩「跟随设备（`PowerShell 7`）」，
点它就是新开一个跑设备 shell 的标签——不会出现一个打不开标签的空菜单；新标签
（`Ctrl+T`、`Ctrl+Shift+T`、`+`、空窗口里的「打开标签」）也一样跑设备 shell，而不是列表里碰巧排第一的那条。

这一个选项管哪些入口：启动的首个标签、`Ctrl+T` / `Ctrl+Shift+T`、标签栏尾部的 `+`、没有标签时窗格里的
「打开标签」，全都按它——与 Windows Terminal 的说法一样（「单击 '+' 图标或通过键入新的选项卡键绑定时
打开的配置文件」）。它**不管**这三处：复制标签（`Ctrl+Shift+D`）与拆窗格跑的是**当前标签**的 profile，
因为那两件事说的是「把眼前这个再来一份」；`Ctrl+Shift+数字` 和 `▾` 里选中的条目当然跑你选的那个。

标签叫什么：标签自己给的名字 > 程序设的标题（shell 会用转义序列设标题，路径不算）> profile 名 >
程序名（`pwsh`、`cmd`、`zsh`，取自 shell 留在标题里的路径）> 它启动的 shell（`bash`、`pwsh`，
探测到的设备 shell 的程序名）> 「跟随设备」。第五级是给没有 profile 名的标签用的：
shell 还没设标题时，列表里至少写清它跑的是什么。最后一级只在机器上探测不到任何 shell 时出现。
窗口标题跟着标签走。

## 8. 配色方案

`colorScheme` 按顺序找名字：

1. `schemes` 里同名的自定义方案（只写部分字段时，没写的沿用同名内置方案）；
2. 内置方案（取值同 Windows Terminal 的 `defaults.json`）：Campbell、Campbell Powershell、
   Solarized Dark、Solarized Light、Tango Dark、Tango Light、Vintage；
3. Ghostty 的 **617 套**主题，名字照抄即可（`Dracula`、`Gruvbox Dark`、`One Half Dark`…）；
4. 都没有 → 回退到 `theme` 对应的默认配色（暗：VS Code 调色板；亮：同源亮色）。

`theme` 决定窗口自己的颜色（标签栏、按钮、对话框与选中色），`colorScheme` 只决定终端里画什么，
两者互不影响：浅色窗口里可以开着深色终端，深色窗口里也可以开着浅色终端。取值：

- `system`：窗口跟随系统的明暗（用程序自带的浅色或深色）；
- `light` / `dark`：窗口指定浅色或深色，不理系统；
- 任意**方案名**（内置、Ghostty 的 617 套，或 `schemes` 里自己写的）：窗口用那个方案的背景与
  前景，强调色取方案调色板的第 5 色（各家的蓝）。选了方案就不再跟随系统，明暗由方案自己的
  背景决定。设置页的「主题」下拉列出 11 个挑过的方案：

  Nord、Catppuccin Mocha、Catppuccin Latte、Gruvbox Dark、Gruvbox Light、Rose Pine、
  Rose Pine Dawn、Kanagawa Wave、Dracula、Solarized Dark、Solarized Light。

  想用别的方案，直接在 `settings.json` 里写名字即可（`"theme": "Vesper"`），不必在下拉里出现。

窗口里唯一跟着终端走的是活动标签：它的底色与前景就是当前窗格的底色与前景，所以标签条上那块
面与下面的终端连成一片，看不出接缝。其余部分——标签条、别的标签、分栏线、对话框、输入框——
都照 `theme` 画。终端没写 `colorScheme` 时，默认配色按 `theme` 的明暗挑：`system` 跟系统，
`light` / `dark` 照字面，方案名看它自己的背景。

### 自己写一套方案

「外观与排版」页的「复制为自定义配色」把当前方案整份复制进 `schemes` 并选中它，之后改颜色即可。
副本的名字取自它复制自的**基名**，而不是另一份副本：`Campbell` 复制出 `Campbell (custom)`，
再复制还是从 `Campbell` 起名（`Campbell (custom 2)`），不会叠成一串 `(custom) (custom)`。

列表里自己写的方案在行尾有 `×`：指针停在那一行、或那一行正被选中时出现，点一下就从草稿里删掉。
删掉的正是当前方案时，终端回到它复制自的那套；那套也没了则回到默认的 Campbell。
复制与删除都只改草稿，点「保存」才写回文件；内置方案与 Ghostty 的 617 套只读，没有 `×`。

选方案只在下面这张列表里：行首的小方块是那套方案的底色（中间那道杠是它的文字色），当前方案那行
底色更亮、名字加粗，卡片的头一行写着当前方案的名字与同样的方块。列表六百多条，靠搜索框找：边打
边筛，回车取剩下的第一条。上面那块预览会把选中的方案立刻画出来，不必保存就能一套套看过去。

## 9. 设置页

`Ctrl+,` 开一个没有窗格的标签页（已打开则切过去）。左栏是固定的六项——「常规与启动」「终端与交互」
「外观与排版」「配置文件」「快捷键」「高级与系统」——顶上还有一个搜索框，表单改的是内存里的设置，
每帧与已应用值比较，不同就应用一次（幂等）。整页只有窗口一个底色，左栏与底部那条只用一条细线
分开，左栏选中的那一项带一块浅底——不会出现半边灰半边黑。

左栏顶上的搜索框按设置项的名字、所在的页面以及常用关键词（`cursor`、`opacity`、`scrollback`、`paste`、
`theme`、`keybinding` 等）跨页检索：命中项列在左栏里，每行写着设置项的名字与它所在的页面，点一下
就切到那一页；一个都没命中时说「没有匹配的设置」。清空搜索框回到六项导航，切页时也会自动清空。

右栏顶上写着这一页管什么，下面按组是一张张卡片：每行左边是这一项的名字与一句说明，控件靠右；
要整行的控件（命令行、参数、起始目录）在说明下方；「高级」页的「重置」是红卡片，放在最后。

- **改了就生效**：语言、界面主题、快捷键、profile 列表、字体/配色/选中即复制、滚轮倍数、最小对比度、窗口透明度与置顶、底色。
- 「常规与启动」（`general`，旧名「启动」仍指这一页）分三张卡片：**语言与启动**（默认配置文件、语言、起始目录）、
  **窗口与标签页**（新标签位置、标签宽度、标题跟随窗格、窗口置顶、每标签窗格上限）、
  **关闭行为**（关最后一个标签时关窗口、关闭确认、关闭窗口前确认）。
- 「常规与启动」页的「语言」是一个下拉：「跟随系统」加每种译文自己的名字（`简体中文`、`English`），
  来自 `locales/` 里的语言文件；选完立即重画，选「跟随系统」时按系统语言匹配，匹配不到就用英文。
- 配色方案只在「外观与排版」页里选（列表可搜索、行首带色板、回车取第一条、右侧预览、可复制为自定义、删掉自己写的）；
  字体、字号、行高、光标、内边距、主题与透明度也在这一页，顶上那块是实时预览区，往下滚时它吸在
  页面顶上不动（字段从它下面滚过），改字体、行高、光标时一直看得见。
- 「配置文件」是页内主从两栏：左边列配置文件，右边编辑选中的那条，新建、复制、隐藏与删除都在页内完成；
  左栏列出全部配置文件（隐藏的也在，带「已隐藏」），隐藏由右侧字段里的「隐藏」开关或卡片底的「隐藏」
  按钮设置，保存后生效。
- 「终端与交互」（`interaction`）也分三张卡片：**鼠标与滚动**（选中即复制、右键行为、滚轮倍数）、
  **剪贴板与安全**（剪贴板读取、剪贴板写入、多行粘贴确认）、**缓冲区**（回滚缓冲）。
- 「关闭行为」里的「关闭确认」是三选一（有程序运行时 / 总是 / 从不），改完立即对下一次关闭生效。
- 「关闭行为」里的「关闭窗口前确认」（`confirmCloseWindow`，默认开）管窗口怎么消失：窗口里有两个及以上标签时，
  标题栏的 `×` 与 `Alt+F4` 都先问一句「关闭窗口？」，并说出几个标签会跟着走；只开着一个标签时不问，
  答「取消」就什么都不做，窗口与标签都留着。
  「高级」页的「删除设置并重启」有自己的确认框，那次关闭不再叠一问。
- **主要在新建标签或窗格时生效**：内边距与内边距颜色、光标形状与闪烁、滚动缓冲、右键行为、剪贴板读取与写入。
  想立刻看到这些改动的效果，就新开一个标签。
- 「保存」写回文件并更新基准值；「放弃」回到上次保存的状态；有未保存改动时关这个标签先问一句。
- 「保存」前会校验草稿（字号、行高、内边距、透明度、滚动缓冲、滚轮倍数、最小对比度、可枚举项与窗格数
  都要在范围内）。不通过时不写文件、不离开当前页，草稿原样留着：页面顶部出现一条红底横幅，
  逐条写明哪里越界（如 `font.size must be between 4 and 200`），底栏此时只说「没有保存：改正后再存，或放弃」。
  横幅一直留到你改正后保存成功，或放弃草稿。
- 底栏最左的「打开设置文件」用桌面关联的程序打开 `settings.json`（还没有文件时先把当前草稿写进去，
  保证点开就有东西可改）；打不开时（Linux 桌面不一定有关联的编辑器）底栏会说原因，
  也可以到「高级」页用「设置目录」自己找文件。
- 保存前会检查文件是否被外部改过：已改过则拒绝保存并提示，需先放弃草稿、重新载入。
  有草稿时外部改动不会覆盖草稿，只提示。
- 「操作」分组按动作目录分组（标签页 / 窗格 / 查找 / 窗口 / 配置文件）列出**全部动作**，
  不只列文件里已有的键位：没绑定的动作键位格显示 `无`，点一下就能录一个新键。
  录制监听整张键名表（字母、数字、`F1`–`F12`、方向键、`comma`/`minus`/`equal` 等），
  所以 `ctrl+comma` 这种键也能录；再点一次同一格取消录制。
- 顶部的搜索框按动作名、动作 id 或键位过滤；右边的「仅看已修改」只留改过键的动作（带当前条数）。
- **一个动作只跑一个键**：键位格列出该动作**当前的**全部键（`tab.new` 默认就是
  `ctrl+shift+t · ctrl+t`；格子窄时打省略号，鼠标停上去看全）。录了新键，它原来的键一起作废
  （录完只剩新的那个）。
- 改过键的动作带「已修改」标签：`重置` 回到默认键（鼠标停上去能看到默认是什么），
  `删除` 让它一个键都不跑。两个按钮在该没事干时是灰的，但位置不变，行不会跳。
- 与其它动作冲突时那一行标红（格子里只要有一个键冲突就整格标红），
  顶栏同时提示「有键位绑给了不止一个操作」（文件里真有冲突时才出现）——冲突不会自动解，得自己改。
- 数字编号的动作（`tab.goto.N`、`profile.N`）每组默认只露前三项，其余折起来，
  用「展开其余 n 项」看全、「收起」折回去；在搜索或「仅看已修改」时全部展开。
- 录完立即生效，但**要保存才写进文件**。
- 「高级」页做的是不常用、也不需要保存的事，改的是文件本身而不是草稿：
  - **重新探测**：按现在装的东西重写内置 profile 的命令行；探测不到的隐藏，回来的重新显示；
    名字、颜色、目录保留。做之前问一句。
  - **删除并重启**：删掉 `settings.json` 并启动一个新窗口，它会写入默认值并像第一次启动那样探测。
    做之前问一句；新窗口没起来时旧窗口留着，不把你关在门外。
  - **设置目录**与**程序目录**：用文件管理器打开。

## 10. 查找与命令面板

**查找**（`Ctrl+Shift+F`）：在焦点窗格的终端里搜文本，浮在右上角。`Enter` 下一个、
`Shift+Enter` 上一个、`Esc` 关掉并清掉高亮。匹配忽略 ASCII 大小写，状态行显示
`第几个 / 共几个`。查找栏开着时键盘留在查找框，不还给终端；切到没有终端的标签页（如设置页）
后查找栏自动收起。

**命令面板**（`Ctrl+Shift+P`）：列出全部动作（含当前快捷键）、当前打开的标签（切过去）、
以及可用的 profile（用它的新开标签）。输入即过滤：标题按字母顺序模糊匹配（词首与连续字母加分），
也接受分组词与动作名的前缀（如 `pane` 列出所有窗格动作）。上下键移动、`Enter` 执行、`Esc` 关闭。

## 11. 出问题时

先跑 `wt-go diag`：它把这台机器上能查的都查了（路径、原生库、每个 profile 能不能启动、
日志在哪），失败的检查带一个编号。日志与崩溃日志在 `%LOCALAPPDATA%\wt-go\`
（Linux `~/.config/wt-go/`）。

每个编号的意思、怎么确认、改什么，以及 `wt-go mcp` 怎么把现场交给 AI，
都在 [故障排查.md](故障排查.md)；MCP 的完整说明见 [MCP.md](MCP.md)。

## 12. 与 Windows Terminal 的差异

- 配置不兼容：WT 的 `profiles.list` / `actions` 结构不认，wt-go 用自己的扁平结构，迁移需手抄。
- 不做 `defaults.json` 两层合并。
- `rightClick` 的"忽略"值是 `nothing`，不是 `ignore`。
- `language` 用 BCP 47 标签（`zh-Hans` / `en`，`""` 跟随系统），不是 WT 的 `zh-CN` / `en-US`（这两个仍能读，按 `zh-Hans` / `en` 处理）。
- 每个 profile 独立字体未做（字体是全局的）；profile 图标先只做颜色标记。
- 未做：标签搜索、焦点标签放大、交换窗格、分屏广播输入、背景图/亚克力、复古 CRT、
  Quake 模式；`startOn: restore`（会话恢复，见阶段 5）。
- Windows 上程序问不到终端的配色与深浅（pi 之类会退回自己的默认色），读剪贴板也拿不到答复：ConPTY 只把
  答复留在它自己那边，wt-go 一概不写回去（ADR-72、ADR-73）。Windows Terminal 能答是因为它自己解析 ConPTY。
