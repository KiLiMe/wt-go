# 使用说明

wt-go 是一个 Windows Terminal 风格的终端：标签、分栏、profile、配色方案、可配置快捷键，
配置文件是一份手写友好的 `settings.json`。这份文档讲怎么用；代码地图见
[代码导读.md](代码导读.md)，取舍理由见 [decisions.md](decisions.md)，阶段状态见 [plan.md](plan.md)。

## 1. 运行环境

- **Windows 10 1809+ / Windows 11**：主要支持与验证目标，用 ConPTY 起 shell。
- **Linux / macOS**：有 pty 与平台路径实现，可交叉编译，属实验性；首轮真机验证结果见第 12 节。
- **Go 1.27+**（`go.mod` 写 `go 1.27.3`）。
- **mygo v0.8.3+**：终端内核来自它的 `plugins/terminal`（libghostty-vt）。
- 发布产物是便携包：`wt-go.exe` 与同目录的 `ghostty-vt.dll`，解压到任意位置双击即用，
  无 Electron、无 webview、不写注册表。

## 2. 构建与运行

```pwsh
pwsh .\build.ps1                  # 产物固定为 build\windows-amd64\wt-go.exe
.\build\windows-amd64\wt-go.exe
```

产物固定在 `build\windows-amd64\wt-go.exe`，方便反复真机测试（`build\` 已在 `.gitignore` 里）。
脚本还有三个开关：

| 参数 | 作用 |
| --- | --- |
| `-Test` | 编译前先跑 `go vet ./...` 与 `go test ./internal/...` |
| `-Clean` | 先删掉 `build\` 再编译 |
| `-Package` | 换成 mygo 打包，产物在 `dist\`（不造安装器） |

正在运行的那个 exe 占着输出文件时 Windows 会拒绝覆盖，脚本会报出 PID 并停下，关掉窗口再编译即可。
开发时也可以直接用 `go run .`。发布包用 mygo 自己的构建命令，
它把原生库、`.deb`、`.tar.gz`（含 `install.sh`）与 `PKGBUILD` 一起产出：

```pwsh
go tool mygo build -platform windows/amd64 -o dist
```

版本号、包名、Linux 依赖写在 [mygo.json](../mygo.json)。发布用标签触发
（`mygo.json` 的 version 必须与标签一致）：

```pwsh
git tag v0.2.0
git push origin v0.2.0
```

标签触发的发布只给两个便携包，没有安装器、也没有 `.deb`：

| 资产 | 内容 |
| --- | --- |
| `wt-go_<version>_windows-amd64_portable.zip` | `wt-go.exe`、`ghostty-vt.dll`、`LICENSE` |
| `wt-go_<version>_linux-amd64_portable.zip` | `wt-go`、`libghostty-vt.so`、`wt-go.desktop`、`LICENSE` |

解压后直接运行。设置与配色方案仍在用户配置目录（Windows `%LOCALAPPDATA%\wt-go\`，
Linux `~/.config/wt-go/`），所以换一个解压位置不会丢配置。

exe 的图标、「属性 → 详细信息」与 manifest（高 DPI、控件外观）都由 `go tool mygo build`
在打包时注入，`build.ps1` 走的也是这条路，所以本地构建的 `wt-go.exe` 与发布版一致
（版本号取自 `mygo.json`）；`go build` 直接出的裸 exe 没有这些资源。改了
`resources\icon.png` 的图案后重画一次：

```pwsh
go run ./tools/genicon           # 重画 resources\icon.png
```

原生库 `libghostty-vt` 的查找顺序是 `$MYGO_GHOSTTY_VT` → 打包资源 → 可执行文件同目录 →
`~/.cache/mygo/natives/<sha256>/`，都没有才联网下载（2 分钟超时、SHA-256 校验）。
断网环境下把它放到 `wt-go.exe` 旁边即可。

## 3. 窗口与标签

标签栏就是窗口标题栏：空白处可拖动窗口，双击切换最大化。三个平台都一样，标题栏的配色与终端一致，
不受桌面主题影响；活动标签就是终端的底色，与下面窗格连成一片，所以它比标签栏矮一点、四角是圆的、
与窗口左边留一道缝，顶边还有一道 2 DIP 的强调色细线（主题的强调色，一般就是方案调色板里的蓝）
——标签与窗格同色时靠它一眼分辨。标题栏高 40 DIP，与 Windows Terminal 的一样高。
Linux 上窗口按钮的**位置与顺序跟随桌面**（`gtk-decoration-layout`，GNOME 默认在右侧、
Ubuntu 在左侧），Wayland 下由合成器画标题栏的桌面（KWin、Hyprland、Sway）则不画，交给合成器。

`+`、`▾`、滚动用的 `❮`/`❯`、标签上的 `×` 在指针移上去时浮出一层更亮的底色、图标变亮，
与窗口右上角的三个按钮一致；其中关闭按钮悬停时底色变红（Windows 的做法）。

| 操作 | 方式 |
| --- | --- |
| 新建标签 | `Ctrl+Shift+T`（或 `Ctrl+T`）、条带上的 `+`、右键菜单 |
| 切换标签 | `Ctrl+Tab` / `Ctrl+Shift+Tab`、`Ctrl+1`…`Ctrl+9`、点击、`Ctrl+滚轮` |
| 关闭标签 | 标签上的 `×`、中键点击、右键菜单（`confirmClose` 为 `running` 时，标签里还有程序在跑就先问一句） |
| 重命名 / 置色 | 右键菜单；颜色默认随 profile。设置标签页不是终端，右键菜单只有关闭项（没有重命名、复制） |
| 拖拽排序 | 按住标签左右拖（按名字或空白处都行） |
| 标签放不下时 | 标签条自己横向滚动：两端出现 `❮`/`❯`（`❯` 在 `+` 左边），一次一个标签；滚轮直接拨；到头的那个按钮变淡 |
| 用某个 profile 新建 | 标题栏的 `▾` 下拉菜单，或 `Ctrl+Shift+1`…`Ctrl+Shift+9` |
| 新标签的位置 | `newTabPosition`：`last`（默认）或 `first` |
| 标签宽度 | `tabWidth`：`compact`（默认，随名字）或 `equal`（等宽） |

标签名跟随 shell 报告的标题；`titleFromActiveTerminal` 为真时也随有焦点的窗格变化。
窗口标题栏的 `×` 目前不会拦还在跑的 shell（未保存的设置改动会丢弃）。

标签再多也不会把名字和 `×` 挤没：每个标签有最小宽度，放不下时是标签条滚动，不是标签压缩。
`+`、一条竖分隔线、`▾` 跟在最后一个标签后面，但**不在滚动的标签里**：标签放得下时它们紧贴最后一个标签，
放不下时它们贴到 `❯` 右边固定住，所以再多标签也是一个标签的距离就能新建，不用滚到最后；
右边仍留一段固定的空白专门用来拖窗口，所以标签排满时窗口照样能拖。

## 4. 分栏

一个标签是一棵窗格树，最多 `maxPanes` 个窗格（默认 4，`0` 为不限）。

| 操作 | 方式 |
| --- | --- |
| 自动切分（先竖后横） | `Alt+Shift+D` |
| 纵向切分（左右） | `Alt+Shift+Right` |
| 横向切分（上下） | `Alt+Shift+Down` |
| 焦点移到相邻窗格 | `Alt+左/右/上/下`，或点击 |
| 关闭窗格 | `Ctrl+Shift+W`（最后一个窗格时关标签） |
| 关闭标签内其它窗格 | `Alt+Shift+W` |
| 调整比例 | 拖动窗格之间的分割线（每格至少 40dp） |

焦点移动按几何判定：同方向、跨度重叠最多者优先，其次最近 —— 树序不等于视觉相邻，
所以 `Alt+Left` 一定去左边那个，而不是"树上的上一个"。

## 5. 快捷键

默认值与 Windows Terminal 对齐，全部可在 `settings.json` 覆盖，或在设置页「操作」分组录制。
设置页把动作目录里的每一条都列出来，没有默认键的动作（例如「关闭标签」）也在里面，
显示为 `无`，点一下就能给它分配一个键。
完整动作清单与键位字符串写法见第 6 节。

标签：`Ctrl+Shift+T` 新建、`Ctrl+Tab` / `Ctrl+Shift+Tab` 前后切换、`Ctrl+1`…`Ctrl+9` 直选、
`Ctrl+Shift+D` 复制当前标签、`Ctrl+Shift+1`…`Ctrl+Shift+9` 用第 n 个 profile 新建。

分栏：`Alt+Shift+D` / `Alt+Shift+Right` / `Alt+Shift+Down` 切分，`Alt+方向键` 移焦点，
`Ctrl+Shift+W` 关窗格，`Alt+Shift+W` 关其它窗格。

设置与面板：`Ctrl+,` 打开设置、`Ctrl+Shift+F` 查找、`Ctrl+Shift+P` 命令面板。

终端插件自带的键（未经 wt-go，由 `mygo/plugins/terminal` 处理）：

| 键 | 动作 |
| --- | --- |
| `Ctrl+Shift+C` / `Ctrl+Insert` | 复制选中 |
| `Ctrl+Shift+V` / `Shift+Insert` | 粘贴 |
| `Ctrl+Shift+A` | 全选 |
| `Ctrl+C` | 有选中时复制，否则发给程序（可配） |
| `Ctrl+滚轮` / `Ctrl+=` / `Ctrl+-` / `Ctrl+0` | 放大 / 缩小 / 重置字号 |
| `Ctrl+Shift+K` | 清屏 |
| `Shift+PageUp` / `Shift+PageDown` | 翻页 |
| `Ctrl+Shift+Home` / `Ctrl+Shift+End` | 滚到顶 / 底 |
| `F11` / `Alt+Enter` | 全屏 |
| `Ctrl+Shift+Space` | 下拉菜单 |

不在表内的键一律发给终端里的程序。要把某个默认快捷键让给程序，删掉对应的 `keybindings` 条目；
现在不要写 `none`，它不会实现透传。

## 6. 设置文件

配置文件在 Windows 上是 `%LOCALAPPDATA%\wt-go\settings.json`，Linux/macOS 上是
`~/.config/wt-go/settings.json`（UTF-8、无 BOM）。首次启动若不存在则写入默认值，
之后被监视并热重载（约一秒内生效）。

写入采用临时文件、同步后原子替换，不留半截配置；已有文件的权限与软链接会被保留。
解析失败或数值越界时**继续使用当前可运行的值**，并把坏内容归档为
`settings.json.bad-<YYYYMMDD-HHMMSS>`（重名追加序号），原因显示在设置页底部。
设置页读写同一份文件，不另存一份。

### 6.1 完整示例

下方 `//` 只是说明，实际文件必须是纯 JSON。


### 6.2 动作名

`tab.new`、`tab.close`、`tab.next`、`tab.prev`、`tab.duplicate`、`tab.goto.N`（N 从 1 起），
`pane.split.auto`、`pane.split.right`、`pane.split.down`、`pane.focus.left`、`pane.focus.right`、
`pane.focus.up`、`pane.focus.down`、`pane.close`、`pane.closeOthers`，
`find.open`、`palette.open`、`settings.open`、`profile.N`（第 N 个 profile，按菜单顺序）。

写了未知动作或解析不了的按键，该条不会执行动作，但**未知动作仍可能接管那个按键**。
要把按键交给终端，请删掉该条，而不是写 `none`。

`keybindings` 是整张表：写了就完全取代默认键位，不是"在默认之上叠加"。
另外，默认键位会随版本增加，已存在的 `settings.json` 自带完整列表，**不会自动获得新默认键位**；
需要的话在设置页点「恢复默认」，或删掉这个字段让程序重新生成。

### 6.3 键位字符串

修饰键 `ctrl`（或 `control`）、`shift`、`alt`、`win`（或 `super`/`meta`），键名小写：
`a`–`z`、`0`–`9`、`f1`–`f12`、`left` `right` `up` `down` `home` `end` `pageup` `pagedown`
`insert` `delete` `space` `tab` `enter`（或 `return`）`escape` `backspace` `minus`
`comma` `period` `equal` `slash` `semicolon` `quote` `backslash`，例如 `"ctrl+shift+t"`。
`plus` 与 `f13` 以上暂不支持。解析不了的那条会被丢弃，对应动作**不会**退回它的默认键。

### 6.4 路径写法

`startDirectory` 与 profile 的 `dir` 在启动标签时展开：开头的 `~`（含 `~/`、`~\`）是主目录；
`%NAME%`、`$NAME`、`${NAME}` 是环境变量，两个平台都认。变量不存在时原样保留，
写错的路径会在界面上显形，而不是悄悄变成空路径。

### 6.5 数值范围

越界时**整份文件被拒绝**，继续使用当前值并提示原因。常用范围：字体 4–200、行高 0.5–4、
内边距 0–256、透明度 0–1、滚动缓冲 0–1024 MB、窗格数 0–64、启动尺寸列/行 0–1000。
设置页的 +/- 控件覆盖更窄的范围，手写超出控件范围的值后点 +/- 可能被夹到控件边界。

### 6.6 起始大小

`startSize` 用列×行表示首屏网格。终端只报告"能放下多少格"不报告一格多大，
所以窗口先长一次、读出差值算出单元格尺寸，再设成恰好放下这些格的大小（两三帧内完成）。
`0` 表示不设。

### 6.7 关闭确认

`confirmClose` 三选一：

| 值 | 行为 |
| --- | --- |
| `running`（默认） | 标签里的 shell 底下还有程序在跑时才问 |
| `always` | 关标签都问一句（包括停在提示符的标签） |
| `never` | 直接关，不问 |

"程序在跑"按**进程树**判断：创建终端后记下 shell 的 PID，关标签时看它底下还有没有别的进程。
所以 `ping -t`、`vim`、正在编译的 `cargo build` 会问，刚打开的提示符不会。
问的时候会**说出是谁**：「还在运行：PING」。看到名字还不明白，就是那个程序没退，去标签里看一眼。

三件事值得知道：

- 只看子进程。shell **自己内部**跑的东西（`Start-Sleep 300` 这种内置命令、`sleep` 这种函数）
  不产生新进程，看不到，关的时候不会问。要它被看见，用外部程序，或者把 `confirmClose` 设成 `always`。
- 判断不了时会换一句话问（「无法判断这个标签里是否还有程序在运行。」），而不是假装没程序。
  什么算判断不了：读不到进程列表（日志里有 `E303`，见 `docs/故障排查.md`），或者这个标签的 shell 还没被认出来。
- shell 已经退出（标签上写着「已退出」）的标签不问，直接关。
- shell 是通过启动器起来的（`scoop` 这类包管理器在 `PATH` 上放的 shim，它会再启动真正的程序）时，
  wt-go 会跟着往下认到真正的 shell，不会把 shim 底下的自己算成「有程序在跑」。

窗口右上角的 `×` 关的是整个窗口，不受这一项约束。
旧文件里的 `true` 读作 `running`、`false` 读作 `never`，保存时会改写成字符串。

### 6.8 字体

`font.family` 是**字体族名**，可以写逗号列表（`"<想要的族名>,monospace"`），取第一个装了的。
不确定写什么就写 `"monospace"`：那是系统的等宽别名，任何机器都有。
设置页的字体栏是个列表，里面是这台机器上装了、并且量出来是等宽的族名，挑一个即可。
这个列表在**第一次打开「配置文件 → 默认值」时**才枚举（不占启动时间），所以刚进页面可能还只有
`monospace`，一两帧后补齐；会话中新装的字体要下次启动才出现在列表里。
终端要求等宽：族名写错或这台机器没装时，系统会回落到某个比例字体，而格宽取“最宽的那个字”，
症状是字距极宽、列对不齐、本该一行的话提前折行。
窗口不报错：它改用系统的 `monospace` 画，并在日志里留一行 `E204`
（`wt-go diag` 的 `last fault:` 能看到，见 `docs/故障排查.md`）。

## 7. profile

### 7.1 从哪来

窗口只在**写第一份 `settings.json`** 的时候扫描一次这台机器上能跑的 shell，把它们作为 profile
写进 `profiles`，设置页里带「内置」小标签。之后 `settings.json` 就是唯一来源：改它、删它、加自己的条目
都算数，启动时不会再探测一遍，你改过的命令行也不会被盖掉。想按现在装的东西重来一次，用
设置页「高级」里的**重新探测**（见 9.5）。

Windows 上按 PATH 找程序：`pwsh.exe`（PowerShell 7）、`powershell.exe`、`bash.exe`、`cmd.exe`、`nu.exe`；
再是注册表里 `wsl` 的每个发行版（`wsl.exe -d <发行版名>`）。**只看 PATH，不去猜安装位置**：
装在 PATH 之外的 shell 不会自动出现，需要自己在设置页加一个 profile。
`C:\Windows\System32\bash.exe` 是 Windows 留给 WSL 的转发壳（跑的就是默认发行版），不算单独的 Bash。

POSIX 上用 `$SHELL`、`/etc/shells` 里认识的 shell（bash、zsh、fish、sh、dash、ksh、tcsh、nu、pwsh；
跳过 `git-shell`、`rbash` 一类），最后 `/bin/sh` 兜底。

程序不在了（卸载了、挪了位置），那个 profile 在你点「重新探测」时被**隐藏**而不是删掉：
重新装回来再探测一次，它还在文件里，点「显示」就回来了。

### 7.2 改、删、隐藏

- 带「内置」的条目可以改名、改颜色、改命令行，改完点保存即可；重新探测会把这些命令行换成现在装的那份，
  名字、颜色、目录保留。
- 「删除」对这些条目是隐藏：探测时还能找到它，删掉也会被加回来，所以只能藏。
- 设置页左栏底部有「显示隐藏的配置文件」勾选框，勾上后列出隐藏的条目（灰字），每个带「显示」。
- 自己加的条目（不带「内置」）删除就是删除。

设置页的「配置文件」页编辑的是**副本**，点保存才写回，所以只是看一眼不会把结果写进文件。
字段：`id`、`name`、`command`、`args`、`dir`、`color`、`hidden`、`discovered`。

## 8. 配色方案

`colorScheme` 按顺序找名字：

1. `schemes` 里同名的自定义方案（只写部分字段时，没写的沿用同名内置方案）；
2. 内置方案：Campbell、Campbell Powershell、One Half Dark、One Half Light、Solarized Dark、
   Solarized Light、Tango Dark、Tango Light、Vintage（取值同 Windows Terminal 的 `defaults.json`）；
3. Ghostty 的 **617 套**主题，名字照抄即可（`Dracula`、`Gruvbox Dark`、`One Dark Two`…）；
4. 都没有 → 回退到 `theme` 对应的默认配色（暗：VS Code 调色板；亮：同源亮色）。

`theme` 决定窗口自己的颜色（标签栏、窗格底色、按钮与选中色）。不写方案名（`system` / `light` /
`dark`）时，窗口也用**终端当前的配色**推导：标签栏比终端底色亮一档，活动标签就是终端底色。
终端里的文字仍只看 `colorScheme`，与 Windows Terminal 的分工一致。取值：

- `system`：跟随系统明暗；
- `light` / `dark`：浅色或深色。

  这三种不改终端配色，只决定原生菜单、对话框与窗口按钮的明暗，以及没写 `colorScheme` 时终端落到哪套
  默认配色；窗口自己的颜色仍从终端方案推导。

- 任意**方案名**（内置、Ghostty 的 617 套，或 `schemes` 里自己写的）：整个窗口换成那个方案的
  背景与前景，强调色取方案调色板的第 5 色（各家的蓝）。选了方案就不再跟随系统，明暗由方案自己的
  背景决定。设置页的「主题」下拉列出 11 个挑过的方案：

  Nord、Catppuccin Mocha、Catppuccin Latte、Gruvbox Dark、Gruvbox Light、Rose Pine、
  Rose Pine Dawn、Kanagawa Wave、Dracula、Solarized Dark、Solarized Light。

  想用别的方案，直接在 `settings.json` 里写名字即可（`"theme": "Vesper"`），不必在下拉里出现。

### 自己写一套方案

「配色方案」页的「复制为自定义」把当前方案整份复制进 `schemes` 并选中它，之后改颜色即可。
副本的名字取自它复制自的**基名**，而不是另一份副本：`Campbell` 复制出 `Campbell (custom)`，
再复制还是从 `Campbell` 起名（`Campbell (custom 2)`），不会叠成一串 `(custom) (custom)`。

列表里自己写的方案在行尾有 `×`：指针停在那一行、或那一行正被选中时出现，点一下就从草稿里删掉。
删掉的正是当前方案时，终端回到它复制自的那套；那套也没了则回到默认的 Campbell。
复制与删除都只改草稿，点「保存」才写回文件；内置方案与 Ghostty 的 617 套只读，没有 `×`。

## 9. 设置页

`Ctrl+,` 开一个没有窗格的标签页（已打开则切过去）。左栏分组，表单改的是内存里的设置，
每帧与已应用值比较，不同就应用一次（幂等）。

- **改了就生效**：语言、界面主题、快捷键、profile 列表、字体/配色/选中即复制、窗口透明度与置顶、底色。
- 配色方案只在左栏的「配色方案」页选（下拉切换、列表可搜索、右侧预览、可复制为自定义、删掉自己写的）；
  「默认值」页管字体、字号、行高、光标、内边距、滚动缓冲与 profile 列表，不再重复一项。
- 左栏「配置文件」组末尾固定两行：「＋ 添加新配置文件」与「显示隐藏的配置文件」勾选框；
  配置文件多时左栏自己滚动，这两行不跟着走。
- 「交互」页的「关闭确认」是三选一（有程序运行时 / 总是 / 从不），改完立即对下一次关闭生效。
- **主要在新建标签或窗格时生效**：内边距、光标形状与闪烁、滚动缓冲、右键行为。
- 「保存」写回文件并更新基准值；「放弃」回到上次保存的状态；有未保存改动时关这个标签先问一句。
- 底栏的「打开设置目录」用文件管理器打开 `settings.json` 所在目录（打开文件本身要桌面有关联的编辑器，
  Linux 桌面不一定有，所以开目录）。
- 保存前会检查文件是否被外部改过：已改过则拒绝保存并提示，需先放弃草稿、重新载入。
  有草稿时外部改动不会覆盖草稿，只提示。
- 「操作」分组按动作目录分组（标签页 / 窗格 / 查找 / 窗口 / 配置文件）列出**全部动作**，
  不只列文件里已有的键位：没绑定的动作键位格显示 `无`，点一下就能录一个新键。
  录制监听整张键名表（字母、数字、`F1`–`F12`、方向键、`comma`/`minus`/`equal` 等），
  所以 `ctrl+comma` 这种键也能录；再点一次同一格取消录制。
- 录完立即生效，但**要保存才写进文件**；与其它动作冲突时那一行标红。
  「删除」把一个动作的键位全部去掉（一个动作可能不止一个键）。
- 「高级」页做的是不常用、也不需要保存的事，改的是文件本身而不是草稿：
  - **重新探测**：按现在装的东西重写内置 profile 的命令行；探测不到的隐藏，回来的重新显示；
    名字、颜色、目录保留。做之前问一句。
  - **删除并重启**：删掉 `settings.json` 并启动一个新窗口，它会写入默认值并像第一次启动那样探测。
    做之前问一句；新窗口没起来时旧窗口留着，不把你关在门外。
  - **设置目录**与**程序目录**：用文件管理器打开。

## 10. 查找与命令面板

**查找**（`Ctrl+Shift+F`）：在焦点窗格的终端里搜文本，浮在右上角。`Enter` 下一个、
`Shift+Enter` 上一个、`Esc` 关掉并清掉高亮。匹配忽略 ASCII 大小写，状态行显示
`第几个 / 共几个`。查找栏开着时键盘留在查找框，不还给终端；切到没有终端的标签页（如设置页）
后查找栏自动收起。

**命令面板**（`Ctrl+Shift+P`）：列出全部动作（含当前快捷键）、当前打开的标签（切过去）、
以及可用的 profile（用它的新开标签）。输入即过滤：标题按字母顺序模糊匹配（词首与连续字母加分），
也接受分组词与动作名的前缀（如 `pane` 列出所有窗格动作）。上下键移动、`Enter` 执行、`Esc` 关闭。

## 11. 出问题时

先跑一条命令，它把这台机器上能查的都查了：

```pwsh
.\build\windows-amd64\wt-go.exe diag          # 人看的
.\build\windows-amd64\wt-go.exe diag --json   # 机器看的
.\build\windows-amd64\wt-go.exe diag --redact # 要贴出去时：个人路径换成占位符
```

输出里有版本与提交、exe 路径、`settings.json` 路径、原生库位置、每个 profile 能不能启动、
日志与崩溃日志的位置，最后是 `checks:`——全部通过时是一行，否则逐个打印 `FAILED E2xx …`。

| 文件 | 位置 |
| --- | --- |
| 设置 | `%LOCALAPPDATA%\wt-go\settings.json` |
| 运行日志 | `%LOCALAPPDATA%\wt-go\wt-go.log`（超过 1 MiB 时下次启动挪成 `.log.1`） |
| 崩溃日志 | `%LOCALAPPDATA%\wt-go\crash-<时间>.log` |
| 坏掉的设置副本 | `%LOCALAPPDATA%\wt-go\settings.json.bad-<时间>` |

配置出错时窗口仍会开，只是用默认值，设置页顶部会显示 `E201:` / `E202:` 开头的一条；
某一条键位写错只是那一条不生效，日志里会有一行 `E203` 指向原文。
每个编号的意思、怎么确认、改什么，都在 [故障排查.md](故障排查.md)。

要把现场交给 AI，可以让它自己读：`wt-go mcp` 是一个 MCP 服务器，五个只读工具（诊断、状态、
设置、profile、日志）读的就是上面这份报告，不需要窗口开着。配置片段在
[故障排查.md](故障排查.md) 第 2 节。

## 12. Linux / macOS（实验性）

首轮真机验证在 Arch Linux + KDE Plasma（Wayland `wayland-1`，X11 走 XWayland `:1`）完成：
构建、`go test -race`、`mygo build` 打包（deb / tar.gz / PKGBUILD）、启动、终端与设置页交互均可用。
发布只取其中的便携 `zip`，`.deb` 与 `PKGBUILD` 不随发布走。

### 12.1 运行库依赖

mygo 在 Linux 上通过 purego 直接调用已加载的 GTK 3 / Pango，**不用 cgo，也不需要 WebKitGTK**。

| 库 | Debian / Ubuntu 包 | 缺失后果 |
| --- | --- | --- |
| `libgtk-3.so.0`、`libgdk-3.so.0` | `libgtk-3-0` | 窗口打不开，进程退出 |
| `libglib-2.0.so.0`、`libgobject-2.0.so.0`、`libgio-2.0.so.0` | `libglib2.0-0` | 同上 |
| `libcairo.so.2` | `libcairo2` | 同上 |
| `libgdk_pixbuf-2.0.so.0` | `libgdk-pixbuf-2.0-0` | 同上 |
| `libpango-1.0.so.0`、`libpangocairo-1.0.so.0` | `libpango-1.0-0`、`libpangocairo-1.0-0` | **窗口能开，但没有任何文字** |
| `libharfbuzz.so.0`、`libpangoft2-1.0.so.0` | `libharfbuzz0b`、`libpangoft2-1.0-0` | 可选；缺则退回简单排版 |

另外需要 **CJK 字体**（Debian `fonts-noto-cjk`、Fedora `google-noto-sans-cjk-fonts`、
Arch `noto-fonts-cjk`），否则中文与框线字符是豆腐块；**glibc ≥ 2.28**；
输入法要设 `GTK_IM_MODULE`（fcitx5 用 `fcitx`，ibus 用 `ibus`），否则中文打不进去。

### 12.2 安装与运行

```sh
# Debian / Ubuntu
sudo apt install libgtk-3-0 libpango-1.0-0 libpangocairo-1.0-0 fonts-noto-cjk
# Fedora
sudo dnf install gtk3 pango pangocairo google-noto-sans-cjk-fonts
# Arch
sudo pacman -S gtk3 pango noto-fonts-cjk

go build -o wt-go .
./wt-go                     # 前台跑：原生库失败只写 stdout 一行 log
GDK_BACKEND=x11 ./wt-go     # 指定后端；不设则自动选，两种都要试
xvfb-run -a ./wt-go         # 无头冒烟：只验证"窗口能开、不崩"
```

数据目录 `~/.config/wt-go/`（`settings.json`、`crash-<时间>.log`、`window-state.json`）。

### 12.3 已知限制

Linux 上标题栏也由程序画（`TitleBarHidden` + `HideWindowButtons`），GTK 不再建 header bar，
所以桌面主题影响不到它；代价是 `gtk-decoration-layout` 被清空时（平铺窗口管理器常见）与
「合成器自己画标题栏」无法区分，两种情形都不画按钮，窗口只能靠快捷键或窗口管理器操作。
X11 与 Wayland 都用同一套自绘标题栏；X11 上窗口由 GTK 自装饰（阴影、缩放边）。
本次改动只在 Windows 上编译并跑过单测，**Linux 真机待实测**：按钮位置与拖动在 X11、
Wayland（GNOME 与 KWin）各验一次。Wayland 下「窗口置顶」受合成器限制可能无效。
`kill -9` 主进程后 shell 可能残留一次
（内核 hangup 与 mygo 关终端时的 SIGKILL 之外，mygo 没有注入 `Pdeathsig` 的扩展点）。

文字颜色靠启动时给 fontconfig 追加一条 `rgba=none` 规则保住（`internal/sys/textcolor_linux.go`）：
mygo 先把字形按灰度光栅化，再把「通道不一致」的字形当成彩色字形（emoji）原样绘制，
而 cairo 1.17.8 之前会在字体声明了次像素顺序时改做次像素光栅化，于是整片文字变成
白底绿 alpha。规则只去掉字体的次像素顺序，不改 GTK 设置、不写用户的 fontconfig 配置；
代价是这些字体不再做次像素抗锯齿（灰阶，观感略软）。上游自己强制灰度之后这段可以删掉。

## 13. 与 Windows Terminal 的差异

- 配置不兼容：WT 的 `profiles.list` / `actions` 结构不认，wt-go 用自己的扁平结构，迁移需手抄。
- 不做 `defaults.json` 两层合并。
- `rightClick` 的"忽略"值是 `nothing`，不是 `ignore`。
- `language` 支持 `zh-CN` 与 `en-US`，其它值按英文处理。
- 每个 profile 独立字体未做（字体是全局的）；profile 图标先只做颜色标记。
- 未做：标签搜索、焦点标签放大、交换窗格、分屏广播输入、背景图/亚克力、复古 CRT、
  Quake 模式；`startOn` 只解析不生效（会话恢复在阶段 5）。
