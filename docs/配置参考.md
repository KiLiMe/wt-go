# 配置参考

`settings.json` 的全字段：在哪、怎么写、每个值能取什么、越界会怎样。
怎么操作窗口见 [使用说明.md](使用说明.md)，键位写法见 [键位.md](键位.md)，
为什么这么设计见 [decisions.md](decisions.md)。

## 1 文件在哪、怎么生效

Windows 上是 `%LOCALAPPDATA%\wt-go\settings.json`，Linux/macOS 上是
`~/.config/wt-go/settings.json`（UTF-8、无 BOM）。首次启动若不存在则写入默认值，
之后被监视并热重载（约一秒内生效）。

写入采用临时文件、同步后原子替换，不留半截配置；已有文件的权限与软链接会被保留。
解析失败或数值越界时**继续使用当前可运行的值**，并把坏内容归档为
`settings.json.bad-<yyyyMMdd-hhmmss>`（重名追加序号），原因显示在设置页底部。
设置页读写同一份文件，不另存一份。

名字（枚举）写错与数值越界不同：**不会拒绝整个文件**，那一个字段回到默认值，
文件其余部分照常生效——设置页因此总显示窗口实际在用的值。认不出的名字只会有
以下几种：`theme`、`startOn`、`cursorShape`、`paddingColor`、`rightClick`、
`clipboardRead`、`clipboardWrite`、`newTabPosition`、`tabWidth`、`confirmClose`。
`language` 不是 BCP 47 标签（含空格、路径之类）时回到跟随系统；是一个合法标签
而没有对应译文（如 `fr-FR`）时保留，界面显示原文语言。
`startDirectory` 与 `colorScheme` 不在此列：前者是路径，后者是任意方案名。

本版本不认识的键（手写的扩展键、以后版本才有的键）**读取时保留、保存时原样写回**：
在设置页改一项再保存，不会让它们消失。同一层级出现重复键时，`Settings` 认识的键
以窗口当前的值为准。已知键内部对象（如 `font`）里的额外键不保留——那个对象整个由
窗口重写。

## 2 完整示例

下方 `//` 只是说明，实际文件必须是纯 JSON。

```json
{
  "language": "zh-Hans",
  "theme": "dark",

  // 启动
  "defaultProfile": "pwsh7",
  "startOn": "default",
  "startDirectory": "",

  // 外观
  "font": { "family": "monospace", "size": 13, "lineHeight": 1.2 },
  "colorScheme": "Campbell",
  "padding": { "x": 12, "y": 8 },
  "backgroundOpacity": 1.0,
  "cursorShape": "bar",
  "cursorBlink": true,
  "scrollbackMB": 10,
  "newTabPosition": "last",
  "tabWidth": "compact",
  "alwaysOnTop": false,
  "titleFromActiveTerminal": false,

  // 行为
  "copyOnSelect": false,
  "rightClick": "copyOrPaste",
  "pasteMultilineConfirm": true,
  "confirmClose": "running",
  "closeOnLastTab": true,
  "confirmCloseWindow": true,

  // 分栏
  "maxPanes": 4,

  // 配色方案（可覆盖内置）
  "schemes": [
    {
      "name": "My Dark",
      "background": "#0c0c0c",
      "foreground": "#cccccc",
      "cursor": "#ffffff",
      "selection": "#264f78",
      "palette": [
        "#0c0c0c", "#c50f1f", "#13a10e", "#c19c00",
        "#0037da", "#881798", "#3a96dd", "#cccccc",
        "#767676", "#e74856", "#16c60c", "#f9f1a5",
        "#3b78ff", "#b4009e", "#61d6d6", "#f2f2f2"
      ]
    }
  ],

  // profile
  "profiles": [
    {
      "id": "pwsh7",
      "name": "PowerShell 7",
      "command": "pwsh.exe",
      "args": ["-NoLogo"],
      "dir": "",
      "color": "#3b78ff",
      "icon": "",
      "hidden": false
    }
  ],

  // 快捷键：按键 → 动作；同一动作写多次＝多个键
  "keybindings": [
    { "key": "ctrl+shift+t", "action": "tab.new" },
    { "key": "ctrl+shift+w", "action": "pane.close" },
    { "key": "alt+shift+d", "action": "pane.split.auto" },
    { "key": "alt+left", "action": "pane.focus.left" }
  ]
}
```

## 3 字段

没写的字段取默认值。带「见」的字段在别处展开，这里只记一行。

| 字段 | 默认 | 取值 |
| --- | --- | --- |
| `language` | `""`（跟随系统） | `""` / `zh-Hans` / `en`：界面语言，BCP 47 语言标签；`zh-CN` 按 `zh-Hans`、`en-US` 按 `en` 读，不认识的值回到跟随系统 |
| `theme` | `dark` | `system` / `light` / `dark`，或方案名（自定义、内置或 Ghostty 的，只有自定义的能在纯函数层认出来，别的名字在 `internal/theme` 解析，认不出按默认深色画）：窗口自己的颜色（标签栏、按钮、对话框、选中色），与 `colorScheme` 互不影响；只有活动标签跟着窗格走，见 [使用说明.md](使用说明.md) 第 8 节 |
| `defaultProfile` | `""`（跟随设备） | profile 的 `id`；**首个标签、`Ctrl+T`/`Ctrl+Shift+T`、标签栏 `+` 与空窗口的「打开标签」都按它**（复制标签与拆窗格按当前标签的 profile）；不写时 wt-go **自己解析设备**：拿启动时探测到的第一个 shell（`pwsh7` → `powershell` → `bash` → `cmd` → `nu` → `wsl:*`），用它的程序与参数开标签，名字与颜色取内置表，不使用设置里任何 profile 的名字/颜色/参数（即使那一条被隐藏）；名字或 shell 对不上（程序删了、条目被隐藏）也回到这里；隐藏的 profile 不进设置页下拉与 `▾` 菜单，可用条目为空时 `▾` 只列「跟随设备」 |
| `startOn` | `default` | `default` / `new`：`default` 按 `defaultProfile` 开首个标签，`new` 忽略 `defaultProfile`、直接开一个设备 shell 的标签（与不写 `defaultProfile` 时同样的解析）；只影响首个标签，`Ctrl+T` 与标签栏 `+` 仍按 `defaultProfile`；会话恢复（`restore`）还没做，见 [plan.md](plan.md) 阶段 5.1，认不出的词按 `default` |
| `startDirectory` | `""`（主目录） | 新标签的起始目录：`current`（wt-go 启动时所在的目录）、`home`（主目录）或一个路径，写法见第 5 节；profile 的 `dir` 优先于它 |
| `font` | `monospace` 13 1.2 | `family`（可写逗号列表）、`size`、`lineHeight`，见第 7 节 |
| `colorScheme` | `Campbell` | 自定义方案 > 内置 7 套 > Ghostty 617 套；只写部分字段时沿用同名内置方案 |
| `padding` | `{12,8}` | 终端网格四周的留白，DIP |
| `paddingColor` | `background` | 留白里画什么：`background`（窗口底色）/ `extend`（最近格子的底色，全屏程序自画背景时铺到边）/ `always`（总是最近格子的底色）；**新标签生效** |
| `minimumContrast` | `0` | 文字与底色的最低对比度（WCAG 0–21）；`0` 原样画，`4.5` 是可读线 |
| `backgroundOpacity` | `1.0` | 窗口整体透明度 |
| `cursorShape` | `bar` | `bar` / `block` / `underline`，认不出按 `bar` |
| `cursorBlink` | `true` | 光标闪烁 |
| `scrollbackMB` | `10` | 滚动缓冲，MB |
| `newTabPosition` | `last` | `last` / `first` |
| `tabWidth` | `compact` | `compact`（名字要多宽就多宽，夹在 116–240） / `equal`（所有标签一样宽，平分标签条，同样夹在 116–240）；标签多到压到 116 还放不下时标签条自己滚动 |
| `alwaysOnTop` | `false` | 窗口置顶；Wayland 下受合成器限制可能无效 |
| `titleFromActiveTerminal` | `false` | 窗口标题跟随有焦点的窗格，而不只是活动标签 |
| `copyOnSelect` | `false` | 选中即复制 |
| `scrollMultiplier` | `1` | 滚轮一格、触摸板滑一下走多远；`1` 表示按系统自己的设置 |
| `clipboardRead` | `deny` | 程序读剪贴板时给什么：`deny` / `allow` / `ask`；**新标签生效** |
| `clipboardWrite` | `allow` | 程序能不能写剪贴板：`allow` / `deny`；**新标签生效** |
| `rightClick` | `copyOrPaste` | `copyOrPaste` / `paste` / `copy` / `menu` / `nothing`（WT 的 `ignore` 在这里叫 `nothing`） |
| `pasteMultilineConfirm` | `true` | 粘贴多行时先问一句 |
| `confirmClose` | `running` | `running` / `always` / `never`，见第 8 节；旧文件的 `true`/`false` 读作 `running`/`never` |
| `closeOnLastTab` | `true` | 关掉最后一个标签时关窗口 |
| `confirmCloseWindow` | `true` | 窗口带着两个及以上标签关掉时先问一句，标题栏的 `×` 与 `Alt+F4` 都算；只开着一个标签时不问（那时关窗口就是关那个标签），「删除设置并重启」有自己的确认框，不再叠问 |
| `maxPanes` | `4` | 每个标签的窗格上限，`0` 为不限 |
| `schemes` | 空 | 自定义配色，字段见下 |
| `profiles` | 探测结果 | 见下；只在写第一份文件时探测，之后它是唯一来源 |
| `keybindings` | 动作目录的默认值 | `[{key, action}]`，写法见 [键位.md](键位.md) |

`schemes[]`：`name`、`background`、`foreground`、`cursor`、`selection` 是颜色字符串，
`palette` 是 16 个颜色（0–7 普通、8–15 亮色）。

`profiles[]`：`id`（键位与 `defaultProfile` 引用它）、`name`、`command`、`args`、
`dir`、`color`、`icon`、`hidden`（隐藏而不是删除）、`discovered`（程序自动发现时写上的标记，
决定它是否带「内置」标签）。`command` 留空表示跑系统的默认 shell；要跑自己的程序就写可执行文件
的路径（设置页在这时给出内联提示与例子）。带 `discovered` 的条目由探测得来，设置页只读它的
`command`。窗口标题、标签名、图标色、从哪发现，见 [使用说明.md](使用说明.md) 第 7 节。

## 4 数值范围

越界时**整份文件被拒绝**，继续使用当前值并提示原因。常用范围：字体 4–200、行高 0.5–4、
内边距 0–256、透明度 0–1、滚动缓冲 0–1024 MB、滚轮倍数 0.1–10、最小对比度 0–21、窗格数 0–64。
设置页的 +/- 控件覆盖更窄的范围，手写超出控件范围的值后点 +/- 可能被夹到控件边界。
从设置页保存时同样按这张表校验：不通过就不写文件，页面顶部横幅逐条写明越界项，草稿保留。

## 5 路径写法

`startDirectory` 与 profile 的 `dir` 认两个词与一种路径：

- `current`：**wt-go 进程启动时所在的目录**（进程 cwd，即 `os.Getwd()` 读到的那个值）。它只在明说时才用：
  文件管理器与桌面只能用「chdir 后 exec」表达「在这里开终端」，但同一个通道里也混着启动器自己的习惯
  （资源管理器给 exe 自己的文件夹、开始菜单给 `%SystemRoot%\System32`），所以默认不认它。
  也**不读 `PWD`**（它由 shell 维护，可能与真实 cwd 不符，Windows 上也没有）。
- `home`：用户主目录（`os.UserHomeDir()`），两个平台同一个词，不必再写 `%USERPROFILE%` 或 `~`。
- 其他值按路径处理：开头的 `~`（含 `~/`、`~\`）是主目录；`%NAME%`、`$NAME`、`${NAME}` 是环境变量，
  两个平台都认。变量不存在时原样保留，写错的路径会在界面上显形，而不是悄悄变成空路径。

`current` 与 `home` 是保留词：真叫这两个名字的目录要写成路径，比如 `./current`。

目录的来源按顺序定：复制标签（`Ctrl+Shift+D`）直接用当前窗格所在的目录；其余情况先看 profile 的 `dir`，
再看命令行 `-d <目录>`（只替这一次运行的 `startDirectory`，不改文件），最后看 `startDirectory`。

两者都留空时就是 `home`，两个平台同一个答案。启动一个窗口时拿不到「人想要哪个目录」：资源管理器给的是
exe 自己的文件夹，开始菜单给 `%SystemRoot%\System32`，Linux/macOS 的桌面会话给的是它自己被启动的地方。
想「在此打开」就明说：`wt-go -d "$PWD"`，或把 `startDirectory` 写成 `current`。
`current` 的 cwd 读不出来时回落到家目录；连主目录都拿不到时才回落到 cwd。

## 6 窗口位置与大小

窗口开在上次关掉时的位置和大小，包括当时是否最大化。这不是 `settings.json` 里的字段：
它记在同一个目录的 `window-state.json` 里（Windows 是 `%LOCALAPPDATA%\wt-go\window-state.json`），
关窗或退出时写入。显示器变了、记下的位置已经不在任何连着的屏幕上时，窗口按记下的尺寸居中打开。

删掉这个文件就等于忘掉：下次按默认的 960×600 居中打开。手写它没有意义（坐标是屏幕绝对像素），
想固定一个大小就在界面上调好、然后正常关窗。

## 7 字体

`font.family` 是**字体族名**，可以写逗号列表（`"<想要的族名>,monospace"`），取第一个装了的。
不确定写什么就写 `"monospace"`：那是系统的等宽别名，任何机器都有。
设置页的字体栏是个列表，里面是这台机器上装了、并且量出来是等宽的族名，挑一个即可。
这个列表在**第一次打开「配置文件 → 默认值」时**才枚举（不占启动时间），所以刚进页面可能还只有
`monospace`，一两帧后补齐；会话中新装的字体要下次启动才出现在列表里。

终端要求等宽：族名写错或这台机器没装时，系统会回落到某个比例字体，而格宽取"最宽的那个字"，
症状是字距极宽、列对不齐、本该一行的话提前折行。
窗口不报错：它改用系统的 `monospace` 画，并在日志里留一行 `E204`
（`wt-go diag` 的 `last fault:` 能看到，见 [故障排查.md](故障排查.md)）。

## 8 关闭确认

`confirmClose` 三选一：

| 值 | 行为 |
| --- | --- |
| `running`（默认） | 标签里的 shell 底下还有程序在跑时才问 |
| `always` | 关标签都问一句（包括停在提示符的标签） |
| `never` | 直接关，不问 |

"程序在跑"按**进程树**判断：创建终端后记下 shell 的 PID，关标签时看它底下还有没有别的进程。
所以 `ping -t`、`vim`、正在编译的 `cargo build` 会问，刚打开的提示符不会。
问的时候会**说出是谁**：「还在运行：PING」。看到名字还不明白，就是那个程序没退，去标签里看一眼。

四件事值得知道：

- 只看子进程。shell **自己内部**跑的东西（`Start-Sleep 300` 这种内置命令、`sleep` 这种函数）
  不产生新进程，看不到，关的时候不会问。要它被看见，用外部程序，或者把 `confirmClose` 设成 `always`。
- 判断不了时会换一句话问（「无法判断这个标签里是否还有程序在运行。」），而不是假装没程序。
  什么算判断不了：读不到进程列表（日志里有 `E303`，见 [故障排查.md](故障排查.md)），
  或者这个标签的 shell 还没被认出来。
- shell 已经退出（标签上写着「已退出」）的标签不问，直接关。
- shell 是通过启动器起来的（`scoop` 这类包管理器在 `PATH` 上放的 shim，它会再启动真正的程序）时，
  wt-go 会跟着往下认到真正的 shell，不会把 shim 底下的自己算成「有程序在跑」。

窗口右上角的 `×` 关的是整个窗口，不受这一项约束。
