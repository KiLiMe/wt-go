# 标签栏与关闭提示修复计划

> 状态：已完成并实测（2026-11-11）；结果见第 8 节
>
> 范围：标签栏显示与交互、标签页滚动、窗口拖动，以及关闭标签时的运行状态判断。

## 1. 背景与问题清单

根据截图和人工复现，需处理以下问题：

1. 多标签场景下标签显示异常。
2. 标签没有稳定的最小宽度，名称、图标和关闭按钮容易被压缩。
3. 标签过多时挤压标题栏拖动区域，鼠标难以找到拖动项，无法移动窗口。
4. 多标签时没有明确的 `<` / `>` 标签导航指示。
5. 鼠标不能在标签区域横向滚动或滑动浏览标签。
6. 关闭标签时的“仍有程序运行”提示需要重新研究，不能简单按 `pwsh`、`bash`、`zsh` 名称判断。

## 2. 现有实现调查结论

### 2.1 标签栏

- `internal/ui/tabs.go` 的 `strip` 将标签栏同时作为窗口标题栏，并通过 `DragWindow()` 拖动窗口。
- `tabs` 当前直接把全部标签放入一行，没有标签区滚动状态，也没有左右导航按钮。
- 紧凑模式使用 `Context.MeasureText` 测量名称，并将名称宽度限制在 `48–240`；等宽模式使用固定宽度 `176`。
- 目前仍需验证：外层 `DragWindow()`、标签拖拽、按钮点击和新增的滚动区域之间的输入事件优先级，避免滚动区覆盖整个标题栏拖动区。

### 2.2 关闭提示判断

当前链路位于 `internal/app/tabs.go` 与 `internal/sys/process*.go`：

1. 创建终端前后获取进程快照，通过 `sys.Spawned` 猜测终端启动的根进程 PID，并写入 `a.shells`。
2. 关闭标签时调用 `a.running(tab)`。
3. 若终端未结束且根 PID 未记录，当前实现保守地返回“仍在运行”。
4. 若进程枚举失败，回退到 `tab.Running()`；只要终端尚未结束就会提示。
5. 进程枚举成功时，只要根 PID 存在任意子孙进程就返回“仍在运行”。
6. 当前 `sys.Proc` 只有 PID、父 PID、名称，不含进程状态、前台进程组、终端会话标识或创建时间。

因此，当前逻辑判断的是“进程树中存在后代”，不是“前台程序正在运行”。源码不能单独证明某台机器上的具体误报原因。

## 3. bash / zsh / pwsh 研究要求

不得按 shell 名称硬编码规则。分别验证以下状态：

| shell | 空闲提示符 | 前台长任务 | 后台任务 | 启动脚本/提示符插件子进程 | shell 已退出 |
| --- | --- | --- | --- | --- | --- |
| `bash` | 不应仅因 shell 本身提示 | 应提示 | 应按会话策略提示 | 记录是否误报 | 不应重复提示 |
| `zsh` | 不应仅因 shell 本身提示 | 应提示 | 应按会话策略提示 | 记录是否误报 | 不应重复提示 |
| `pwsh` | 不应仅因 shell 本身提示 | 应提示 | 应按会话策略提示 | 记录是否误报 | 不应重复提示 |

每次验证至少记录：

- 操作系统与版本；
- shell 及启动参数；
- `confirmClose` 设置；
- 终端根 PID 是否成功记录；
- 关闭判断时的完整进程树；
- 进程枚举是否成功；
- 是否弹出提示及预期结果。

特别注意：macOS 当前复用非 Windows 的 `/proc` 实现，而 macOS 通常没有 Linux 风格的 `/proc`；该路径必须单独验证，不能假设与 Linux 相同。

## 4. 实现约束

### 4.1 标签栏

- 设定并统一标签的最小可操作宽度，保证图标、名称、关闭按钮不互相覆盖。
- 标签区应有独立的可视范围和滚动偏移，不允许无限挤压右侧窗口控制/拖动区域。
- 标签过多时显示 `<` / `>` 导航按钮；按钮只负责移动可视标签范围，不改变标签顺序。
- 支持标签区鼠标滚轮横向浏览；滚轮事件不能误触发终端字号或透明度快捷操作。
- 标签拖拽排序应作用于逻辑标签区；滚动后仍能正确计算拖放目标。
- 标题栏必须始终保留稳定、可发现的窗口拖动区域；该区域不能被标签列表完全覆盖。
- 不改变 `internal/ui` 纯绘制职责；状态变更通过 `ui.Actions` 回传。

### 4.2 关闭提示

- 先保留现有跨平台进程判断的事实记录，再基于实测结果修复，不以 shell 名称作唯一依据。
- 区分：shell 自身、前台子进程、后台任务、提示符插件辅助进程、PTY host、已退出/僵尸进程。
- 需要明确“仍有程序运行”的产品定义：是任意会话子进程、前台进程，还是可由关闭标签终止的进程集合。
- 处理根 PID 未识别、进程快照失败、PID 复用、并发创建标签和子进程重父化等不确定情况。
- 若无法安全判断，应采用明确记录的保守策略，并在确认框文案中避免声称已经识别出具体前台程序。
- Windows Job Object 负责生命周期收尾，不等同于“标签当前有前台任务”的判断依据。
- Linux、macOS、Windows 的进程枚举能力不同，不能只用 Windows 的进程树假设覆盖所有平台。

## 5. 验收标准

### 标签栏

- 1、2、3、5、10、20 个标签时，名称、图标、关闭按钮均可操作，标签不会互相覆盖。
- 标签超出可视范围后，`<` / `>` 指示器出现且可用；当前标签被切换或新建后自动滚入可视范围。
- 鼠标在标签区滚轮可浏览全部标签；滚动期间不会改变终端字号、透明度或窗口大小。
- 标签拖拽排序在未滚动和已滚动状态下均正确。
- 标签很多时，仍能用空白拖动区移动窗口、双击最大化；窗口控制按钮不被标签覆盖。
- 关闭按钮、中键关闭、右键菜单和键盘关闭动作行为一致。

### 关闭提示

- 空闲的 `bash`、`zsh`、`pwsh` 不应仅因为 shell 名称而提示。
- 前台长任务关闭时应提示。
- 后台任务、会话子进程和插件辅助进程的行为按产品定义一致，并有测试记录。
- shell 已退出的标签不应重复提示。
- 进程枚举失败、根 PID 未识别等降级路径有明确测试与日志。
- 至少有纯函数测试覆盖进程树判断；能运行真实环境时，补充 Windows、Linux、macOS 的手工或自动化记录。

## 6. 推荐验证顺序

1. 先验证现有 `a.running` 在三种 shell 和各平台的实际进程树。
2. 明确“占用”的产品定义与确认框文案。
3. 为进程判断抽出可测试的纯函数或输入模型，再修改平台采集层。
4. 独立实现标签栏可视范围、最小宽度、导航和滚轮行为。
5. 验证拖拽排序与窗口拖动事件不冲突。
6. 执行 `gofmt`、`go vet ./internal/...`、`go test ./internal/...`，并完成截图回归。

## 8. 实施结果（2026-11-11）

### 8.1 标签栏

- 标签条拆成：滚动视口 + `❮`/`❯` + `▾` + `+` + 固定 56dp 拖动区。每个标签 `.Shrink(0)`，宽度 = 60/44 + 名字宽，最小 108。
- 箭头只在放不下时出现（`MaxX > 0`），出现后到头的那个淡到 45%（不用 `Disabled`：那会连点击一起失效）；字形用重的 `❮`/`❯`（U+276E/U+276F，18dp），单书名号 `‹`/`›` 在这个尺寸下太细。
- 实测：1/2/3/5 个标签（刚好放下）无箭头；6 个起两端出现 `❮`/`❯`，各走一个标签宽。
- 滚轮在视口的 `HandleInput` 里把 `DY` 转成横向位移（一格 ≈ 99dp），因为 mygo 的 `scrollBy` 只让纵向滚轮动纵向容器。
- `State.RevealTab` 传两帧意图（`revealFrames = 2`），`ui` 对该标签调 `ScrollIntoView`：箭头出现的下一帧视口才变窄，只问一帧的话活动标签会被箭头截掉半个；`Actions` 只新增 `ScrollTabs(by float32)`。
- 标签名 `.Unselectable()`，按住名字拖拽不会变成选字。
- 实测（960×600，本机）：1/2/3/5/10/20 个标签下名字与 `×` 都可点、不重叠；12 与 20 个标签时只显示约 5–8 个，自动滚到活动标签；`❮`/`❯` 各走一个标签宽；空白处拖动窗口位移与鼠标一致（(+80,+40) 与 (-50,-20)）；右侧 56dp 处同样能拖；空白处双击最大化、再双击还原。
- 拖拽排序：headless 测试覆盖（含滚动视口内），真实窗口里拖动也能改变顺序；合成鼠标事件在本机只能稳定送出一次 `WM_MOUSEMOVE`，所以拖拽的实机验证以 headless 测试为主。

### 8.2 关闭提示

- `internal/sys` 新增纯函数 `ShellProc.Activity(all) Activity`（`Idle`/`Busy`/`Unknown`），`Proc` 新增 `State`（僵尸过滤），`Spawned` 加 `taken` 并改取最小 Pid；macOS 改走 `kern.proc.all`。
- `app` 侧：`shells` 存 `sys.ShellProc`，`activity`/`asksClose`/`othersActivity` 取代 `running`，认领表 `taken` 防同时启动时认错，等待窗口 3 秒自适应轮询。
- 文案：`Unknown` 时另说一句（"无法判断……"）；读不到进程列表打 `E303`；`Busy` 时**点名程序**（「还在运行：PING」）。
- 实测：空闲 pwsh 标签中键关闭不提示；`ping -n 300` 前台跑时中键关闭会问「还在运行：PING」；`exit` 之后（标签显示「已退出 (0)」）中键关闭不提示。
- **启动器 shim**：`scoop` 把 `…\shims\pwsh.exe` 放在 `PATH` 上，它再启动真正的 `…\apps\pwsh\current\pwsh.exe`，于是标签的 shell 底下永远有个同名子进程，空闲标签也被判成 `Busy`（提示「还在运行：pwsh」）。
  从资源管理器双击启动必现，从带真 exe 的 `PATH` 启动复现不出来。修法：`sys.Reexec` + `spawned` 找到候选后再看 250ms（`shellSettle`），有同名子进程就用 `reclaim` 把认领换到子进程；`taken` 改成 `map[int]*terminal.Terminal`，`forget` 按终端清干净。
- **已知盲区**：shell 内置的长命令（`Start-Sleep 300`）不产生子进程，看不到，不提示；已写进 `docs/使用说明.md` 6.7 与 ADR-026。

### 8.3 收尾

`gofmt` 无输出、`go vet ./internal/...` 干净、`go test ./internal/...` 全绿（含新增的 `TestActivity`/`TestPrograms`/`TestReexec`/`TestSpawnedTogether`/`TestStripFits`/`TestStripScrolls`）。
