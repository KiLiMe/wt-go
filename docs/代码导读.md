# 代码导读

wt-go 的代码地图：目录职责、包边界、渲染与生命周期、改动前必读的坑。路径一律相对仓库根。
用法见 [使用说明.md](使用说明.md)，取舍理由见 [decisions.md](decisions.md)，阶段状态见 [plan.md](plan.md)，
工程约定见 [../AGENTS.md](../AGENTS.md)。

## 目录

```text
wt-go/
├── cmd/wtgo/main.go        入口，一行 os.Exit(app.Run())
├── internal/
│   ├── app/                应用状态与动作：标签、窗格、设置读写、热重载、命令面板与查找栏的状态、进程生命周期
│   ├── ui/                 只画 State：标签栏（兼标题栏）、窗格、设置页、命令面板、查找栏、对话框
│   ├── action/             动作目录：id、标题、分组、默认键位（纯函数）
│   ├── pane/               窗格树与标签集合：切分、焦点、关闭补位（不做 IO）
│   ├── layout/             窗格树的几何计算（纯函数，不认识终端）
│   ├── profile/            profile 模型与自动发现结果的合并（纯函数）
│   ├── store/              settings.json 的解析、序列化、默认值、范围校验（纯函数）
│   ├── theme/              配色：设置里的方案 > 内置 > Ghostty 617 套（纯函数）
│   ├── sys/                全部 OS 副作用：路径、原子写、归档、Job Object、shell 探测、打开路径、崩溃日志
│   └── i18n/               中英文案（缺条目回落原文）
├── resources/icon.png      图标源
├── mygo.json               go tool mygo build 的包名、版本与打包信息
├── docs/                   使用说明 / 代码导读 / decisions（ADR）/ plan（阶段计划）
└── .github/workflows/      ci.yml（gofmt / vet / test / 试打包）、release.yml（标签发布）
```

## internal/pane 与 internal/layout

- `pane.Node`：`Term` 非空即窗格，否则是 split（`First`/`Second`/`Share`/`Vertical`）。
- `pane.Tab`：`Root *Node` + `Focus *Node`；设置标签页的 `Root == nil`。
- `pane.Set`：窗口里的标签集合（`Tabs`、`Active`、`Front()`）。移除窗格时**返回**被移除的句柄，不关闭进程。
- `layout.Layout(root, rect)`：算出每个窗格与分割线的矩形。分割线 4dp，每个窗格至少 40dp，
  `Share` 在拖动时被夹在两端之内。

## 边界与链路

依赖方向自上而下，`app → ui → {pane, layout, store, theme, profile, action} → i18n`：

```text
cmd/wtgo        → internal/app
internal/app    → action ui pane profile store theme i18n sys
internal/ui     → action pane layout profile store theme i18n (mygo/ui, mygo/plugins/terminal)
internal/theme  → store
internal/pane   → layout (mygo/plugins/terminal)
internal/profile→ store
internal/store  → action
internal/action → i18n
internal/sys    → （无内部依赖；标准库与 golang.org/x/sys/windows）
internal/layout → （无内部依赖）
internal/i18n   → （无内部依赖）
```

`internal/app/deps_test.go` 用 `go list` 读每个包的直接 import 与这张表比对，
并检查 `action`/`i18n`/`layout`/`pane`/`profile`/`store`/`theme`/`ui` 不 import
`os`/`os/exec`/`path/filepath`/注册表 —— 所以纯函数包做不了 IO，数据只能由 `app` 注入。

要点：

- `ui` 绝不 import `app` 或 `sys`：界面只画，动作经 `ui.Actions` 在 UI 线程上回调。
- `ui` 不认识终端：它按 `pane.Layout` 给的矩形摆位置，终端视图由 `app` 提供的 `Tab.Mount` 画。
- `pane` 不做 IO：`Set.Remove` 只把 `*terminal.Terminal` 交出来，`app` 负责 `Close()`。
- `action` 是动作名的唯一来源：键位、`▾`/右键菜单、命令面板、设置页标题都从它取。
- 一个终端只能有一个 `terminal.View` 挂载点（libghostty 的约束）：窗格挂载点每帧重建，
  但 `Term` 句柄是同一个。

## 渲染流程

1. mygo 每帧调用根 `View` → `app.view(c)`：清理已关掉的对话框 → 记内容区 → `apply()`（把改动落到位）
   → `bind(c)`（挂键位）→ 组装 `ui.State` → `ui.View(c, st, a)`。
2. `ui.View` 从下到上：标签条（36dp，兼标题栏）→ 窗格树或设置页 → 覆盖层
   （重命名、确认、命令面板、查找栏）。
3. 状态只在 `app` 改；改完 `Invalidate()` 请求下一帧。终端的标题/退出回调经 `App.Do` 排回 UI 线程。
4. 键盘焦点每帧用 `Element.Focus()` 保持（`AutoFocus` 只在一帧生效）；命令面板/确认框开着时
   标签页不把焦点还给终端，查找栏开着时同样不还。

## 改动前必读

- **`AutoFocus` 只生效一帧**，移动焦点必须用 `Focus()`；焦点窗格每帧重新 `Focus()`。
- **`keybindings` 是整张表**：写了就完全取代默认值。默认键位来自 `action.All()`，
  改默认键只改 `internal/action`，不要另加一份。
- **`ui.Context.Shortcut` 会跳过已被焦点元素处理的键**：输入框吃掉 `Enter`（用 `in.Submitted()` 判断）
  与方向键时，别指望 `c.Shortcut(0, myui.KeyDown)` 还能收到。`OverlayShortcut` 是 `Element` 的方法，
  不是 `Context` 的。
- **`myui.Modal`/`DialogBase` 会在点背景或按 `Escape` 时把 `open` 置 false**：状态用 `*bool`
  绑给它，`app` 每帧看到 false 就丢弃这个对话框。
- **设置页改的是内存**：表单直接写 `a.settings`，每帧与 `a.applied` 比较后幂等应用；
  「保存」才写盘。profile 编辑用副本（`a.editing`），看一眼不会污染文件。
- **热重载以文件字节为准**：有未保存草稿时不覆盖；外部已改过时拒绝保存。
- **关窗格的进程要自己关**：`pane` 只交出句柄；`Terminal.Close()` 只能在 `app` 里调。
- **Windows 子进程收尾靠 Job Object**：`Run` 一开始把本进程加进 `KILL_ON_JOB_CLOSE` 的作业，
  之后所有 shell 自动继承，窗口崩了也不会留下 `pwsh.exe`。
- **坏配置要归档不能吞**：解析失败写 `settings.json.bad-<时间>`，原因给设置页看；
  写盘走临时文件 + 原子替换，保留原文件权限与软链接。
- **依赖表是测试**：新增包/改 import 必须同步 `deps_test.go` 与本文的依赖图，否则 `go test ./internal/app` 失败。
- **Linux 的标题栏交给平台**（`titlebar_linux.go`）：mygo 的 `TitleBarHidden` 在 X11 上没有装饰也没有按钮；
  同时 `c.TitleBar()` 归零，条带右侧让位区随之消失。
- **注释是英文、文档是中文**：与 mygo 上游一致。

## 阅读顺序

1. `cmd/wtgo/main.go` → `internal/app/app.go`（`Run`/`newApp`/`view`/`bind`/`apply`）
2. `internal/ui/ui.go`（`State` 与 `Actions`）→ `ui/tabs.go` → `ui/panes.go`
3. `internal/app/tabs.go`（`act` 的分发）→ `internal/action/action.go`（动作目录）
4. `internal/pane/*` → `internal/layout/layout.go`（窗格树与几何）
5. `internal/store` → `internal/profile` → `internal/theme`（纯函数层）
6. 专项：`app/settings.go` + `ui/settings.go`（设置页）、`app/palette.go` + `ui/palette.go`（命令面板）、
   `app/find.go` + `ui/find.go`（查找栏）、`internal/sys/*`（平台差异）

## 构建与测试

```pwsh
pwsh .\build.ps1 -Test               # 构建到 build\bin\Release\wtgo.exe（-Test 先跑 vet 与测试）
go vet ./internal/... ; gofmt -l .   # 提交前
go test ./internal/...               # 不含 race
go test -race ./...                  # CI 在 Linux 上跑这套
pwsh .\build.ps1 -Package            # 等于 go tool mygo build -platform windows/amd64 -o dist
```

CI（`.github/workflows/ci.yml`）在每个 push 与 PR 上跑 `gofmt`、`go vet`、`go test -race`
（Linux 跑整套与 race，Windows/macOS 跑不带 race 的同一套），并试打包两个平台。
`release.yml` 在标签上出 `wt-go-<version>-linux-amd64.tar.gz`、`wt-go_<version>_amd64.deb`、
`install.sh`、`wt-go-setup-<version>-amd64.exe` 与 `SHA256SUMS`。
