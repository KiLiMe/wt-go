# 代码导读

wt-go 的工程地图：包边界、运行主链路、改动暗坑、构建与发版流程。具体文件与符号按包职责直接用 `rg` 定位，不在此维护逐函数索引。
工程红线见 [../AGENTS.md](../AGENTS.md)，架构决策见 [decisions.md](decisions.md)。

## 1. 包边界与依赖方向

依赖严格自上而下，由 `internal/app/deps_test.go` 用 `go list` 机械校验：

```text
main (根包)      → internal/app
internal/app     → action cli fault layout pane profile store theme i18n sys ui locales
internal/ui      → action icons layout pane profile store theme i18n locales (mygo/ui, mygo/plugins/terminal)
internal/cli     → fault mcp profile store sys
internal/theme   → store
internal/pane    → layout (mygo/plugins/terminal)
internal/profile → store
internal/store   → action
internal/action  → i18n locales
internal/i18n    → locales
无内部依赖的底层包 → mcp, icons, fault, sys, layout, locales
```

- **纯函数隔离**（`TestPure`）：除 `app`、`sys` 外的所有 `internal/*` 与 `locales` 均不可 import `os`、`os/exec`、`path/filepath` 或 Windows 注册表（测试文件仅放过 `io/fs` 读夹具）。
- **`ui` 与 `app`/`sys` 隔离**：`ui` 只画 `ui.State`，所有用户操作经 `ui.Actions` 在 UI 线程回调；终端视图由 `app` 经 `Tab.Mount` 挂载。
- **`pane` 不做 IO**：`Set.Remove` 只把 `*terminal.Terminal` 句柄交回 `app`，由 `app` 调 `Close()`。
- **CLI / 窗口双入口**：`internal/cli.Run` 处理 `diag` / `mcp` / `version` / `help` 后直接退出，只调 `sys` 读盘，不干扰运行中的窗口；无命令时才解析 `-d`/`--dir` 并进入窗口主循环。

## 2. 运行主链路

1. **启动**：`app.Run` 先接管日志（`sys.OpenLog`，便携模式走 `data/logs/`）、挂 `Job Object`（`sys.HoldChildren`）、配置便携路径（`mygo.PathUserData` → `data/config/`）与随包 ConPTY（`sys.UseBundledConPTY`），再建窗口与 `newApp`。
2. **渲染帧**：mygo 每帧调 `app.view(c)` → 清理已关闭的模态框 → `apply()`（比较 `settings` 与 `applied`，幂等同步语言、主题、窗口外观、键位、终端选项）→ `bind(c)`（无模态阻挡时挂载快捷键）→ 装配 `ui.State` → `ui.View(c, st, a)`。
3. **绘制顺序**：`ui.View` 从下到上绘制：标签条（40 DIP，兼标题栏）→ 窗格树或设置页 → 覆盖层（重命名 / 确认 / 关于 / 命令面板 / 查找栏）。
4. **线程与重绘**：终端回调（标题、退出、OSC 7 目录等）经 `App.Do` 排回 UI 线程；状态改动后调用 `Invalidate()` 请求下一帧。
5. **配置文件来源**：仅在首次生成 `settings.json` 时把探测到的 shell 写入 `profiles`；之后文件为唯一来源，后台每秒比对文件字节（`savedData`）热重载。

## 3. 改动前必读（高风险暗坑）

- **`AutoFocus` 只生效一帧**：焦点窗格必须在每帧重调 `Element.Focus()`；模态框或查找栏打开时停止把焦点还给终端。
- **浮层同时只有一个**：命令面板、查找栏、重命名、确认、「关于」统一走 `internal/app/overlay.go` 的 `openOverlay` / `closeOverlay` / `top()`。`myui.Modal` 点遮罩或按 `Esc` 会将 `*bool` 置 `false`，`view` 每帧丢弃已关闭浮层。
- **输入框会吃掉快捷键**：`ui.Context.Shortcut` 会跳过已被焦点控件处理的键（如 `Enter`、方向键），输入框提交应读 `in.Submitted()`。
- **`keybindings` 是整张表替换**：写了就全量覆盖默认键。设置页以动作 id 为键、一个动作只留一个键；按住连发仅对 `Action.Repeats`（翻标签、移焦点）生效。
- **标签宽度一律按加粗量**：`measuredName` 使用 `Context.MeasureText` 并按 `nameBold` 测量，夹在 48–172，再由标签条平分份额（116–240），防止切换活动标签时 `+`/`▾` 按钮左右跳动。
- **设置页两套缓存状态**：表单直接写内存草稿 `a.settings` 实时预览，保存才写盘；`profiles` 页使用工作副本 `a.editing`，`a.schemes` 仅在 `apply` 真正改配置后失效。外部改过文件时拒绝覆盖。
- **未知字段与校验分离**：`store.Parse` 用 `Extra` 保留未知顶层键（不计入 `dirty()`），枚举写错单字段回落默认，数值越界拒绝整份文件并保留 `.bad-<时间>` 归档。新加配置字段须同步 `store.knownKeys`（`TestKnownKeysAreTheFields` 会用反射校验）。
- **单终端只能有一个挂载视图**：`libghostty-vt` 约束每帧重建 `terminal.View` 时必须复用同一个 `Term` 句柄。
- **进程树判断**：Linux 读 `/proc/<pid>/task/<tid>/children`（`sys.Subtree`），Windows/macOS 快照进程表；关闭多个标签共用一帧快照，并下探 Scoop 等启动器 shim 到真正 shell。
- **Win10 顶部 1px 归 mygo（ADR-86）**：当 `TitleBarHidden` 且非最大化/全屏时，mygo 让出客户区第 0 行并在 `WM_PAINT` 里用黑刷让 DWM 的边框线透出；wt-go 不参与颜色。改动换行、surface 位置或标题栏高度（`ui.TitleBarHeight`）时，要在 Win10 上看冷启动首帧与拖动 resize，不要只看 Win11（Win11 这段代码不生效）。
- **Linux 标题栏与文字颜色**：Linux 同样走 `TitleBarHidden` + `HideWindowButtons: true` 自绘标题栏；启动时追加 `fontconfig` `rgba=none` 规则避开 cairo 次像素抗锯齿导致的彩色字形误判。
- wt-go 的 mygo 定制改动统一提交到 `KiLiMe/mygo` 的 `my-go-custom` 分支。同步上游时，拉取 `egoist/mygo` 的 `main` 并合并到 `my-go-custom`，保留定制提交历史。联调通过后，将 `go.mod` 的 `replace` 固定到该分支中已验证提交的 Go 伪版本。

## 4. 构建、测试与发布

```pwsh
# Windows 日常构建与全量检查
pwsh ./Scripts/build.ps1 -Test               # 先跑 go vet ./... 与 go test ./...，产物在 build\windows-amd64\wt-go.exe
pwsh ./Scripts/build.ps1 -Package            # 打包便携 zip 到 dist\
pwsh ./Scripts/build.ps1 -Version 0.3.3      # 校验 mygo.json 版本号（发版对 tag 用）

# 代码生成与质量检查
go tool mygo generate                        # 改了 locales/*.json 后重写 locales/catalog_gen.go（须提交）
go tool mygo i18n check                      # 校验译文覆盖率与占位符类型
uv run tools/genicon/render.py               # 从 resources/icon.svg 生成 resources/icon.png
go vet ./internal/... ; gofmt -l .
go test -race ./...                          # Linux 下跑竞态检查
```

Linux / macOS 使用 `./Scripts/build.sh`（对应参数 `--test`、`--package`、`--expect <版本>`、`--clean`）。

### 版本与发布规则

- **唯一版本源**：`mygo.json` 的 `version`（三段纯数字 `主.次.修订`，暂不支持 `-rc` 等预发布后缀）。构建脚本与 CI 会将其注入 `internal/cli.packagedVersion` 并校验生成物，裸 `go build` 无 `(packaged …)` 后缀。
- **发版流程**：更新 `mygo.json` 的 `version` → 推到 `main` → 打带注释 tag 并推送（`git tag -a v0.3.3 -m "wt-go 0.3.3" && git push origin v0.3.3`）。
- **CI（`.github/workflows/ci.yml`）**：push/PR 跑 `gofmt` / `go vet` / `go test` 与便携包构建；tag 与 `mygo.json` 版本一致时自动生成 `SHA256SUMS` 并发布 Windows / Linux 便携 zip（不发安装器与 `.deb`）。
